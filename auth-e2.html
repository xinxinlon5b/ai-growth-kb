E2 · MLOps / LLMOps + AI 技术栈五层

类型：AI 工程方法论 · 权威标准
来源：DeerFlow 调研报告（2026-09-09） + Google MLOps 实践者指南
中文卡版本：基于 DeerFlow 调研整理 · 2026-09-10

一、定位

这一张讲「企业 AI 落地」和「传统软件开发」有什么不同——
把"调一个 LLM API"升级为"一个完整的 AI 系统工程"。

你的方法论「工具是 0，业务才是 1」在这张卡上被进一步具体化：
AI 不只是"调模型"，是"数据 + 模型 + 编排 + 服务 + 治理"五层缺一不可。

二、AI 技术栈五层

层 做什么 典型组件
数据层 数据采集、清洗、标注、存储、特征工程、向量库 PostgreSQL、Pinecone、Milvus、Weaviate、FAISS
模型层 基础模型、微调、模型注册 GPT / Claude / Gemini / 开源（Llama、Qwen）/ Hugging Face
编排层 提示工程、工作流、Agent 框架、工具调用、RAG 管道 LangChain、LlamaIndex、OpenAI Assistants、自研 Harness
服务层 推理部署、API 网关、扩展、延迟与成本 FastAPI、vLLM、Kubernetes、云函数
治理层 安全、合规、可观测、权限、审计、护栏 日志/监控、IAM、内容安全、NIST AI RMF 对齐

为什么分五层：企业落地失败的常见原因，正是只做了模型层/服务层，而忽略了数据层与治理层。
这就是"7 成脏活在数据层"的工程解释。

三、MLOps / LLMOps 流水线（Google 定义）

MLOps 实践者指南（Google Cloud Architecture Center）定义了 AI 落地的标准流水线：

  1. 用例识别与价值定义——选对场景，明确业务问题 + 衡量指标
  2. 数据工程——数据采集、清洗、标注、版本化、特征工程、训练/验证/测试切分
  3. 模型开发与实验——特征选择、训练、超参调优、实验追踪（MLflow 等）
  4. 模型评估——留出集 + 准确率 / F1 / 业务指标 / 安全公平性
  5. 模型部署——封装成推理 API
  6. 监控与持续训练——数据漂移、概念漂移、性能退化 → 触发重训练
  7. 治理与合规——版本化、文档、审批、访问控制、生命周期追溯

https://cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning

四、LLMOps vs MLOps 的差异

大模型（LLM）时代的 LLMOps 在 MLOps 基础上，新增了 5 个关注点：

新增点 为什么 你的方法论对应
微调（Fine-tuning） 取代/补充"从零训练" 基础模型已强，无需从零 知识库项目基本不需要微调
实时生成计算（推理延迟、Token 成本） LLM 推理贵，1 个汉字 ≈ 1.5-2 Token 你方法论「先免费白嫖」
向量数据库编排（RAG 检索） LLM 没有私有知识 你的 SOP-03「进厂先找数据」
提示工程 + Prompt 管理 提示词是一类新"代码" 你方法论「AI 时代顶级能力=会提问」
RAG（检索增强生成） 私有知识 + 模型 = 不重训也"懂"业务 知识库项目的标准架构

五、Gartner AI 成熟度 5 级

级别 名称 特征
1 Awareness（意识） 了解 AI，尚未系统应用
2 Active（活跃） 试点项目，零散应用
3 Operational（运营化） AI 进入生产，有治理雏形
4 Systemic（系统化） 嵌入多个业务，规模化、标准化
5 Transformational（变革级） 重塑业务模式，创造新价值

7 个支柱（每级用这 7 个维度评分）：战略 / 组织 / 人才 / 数据 / 技术 / 治理 / 文化与变革

你的客户大多数在 2-3 级之间。定位清晰才能谈下一步。

六、AI Agent 架构（单 Agent）

一个 AI Agent 不是"一个 LLM"，是循环系统：

┌─ LLM 核心（推理与决策）──┐
│  ↓                       │
│  感知 → 思考 → 行动 → 观察（循环）
│  ↓                       │
├─ 记忆（短期 + 长期）─────┤
├─ 工具（搜索/计算/代码/API）─┤
└─ 规划（ReAct / Plan-and-Execute）─┘

这是 Anthropic A2「Harness」的另一种工程化表达。

七、RAG 架构（5 步流程）

  1. 文档切分（Chunking）——把私有文档切成小片段
  2. 向量化（Embedding）——用嵌入模型把片段转成向量
  3. 存入向量数据库——建立可检索索引
  4. 检索（Retrieval）——用户提问时检索最相关片段
  5. 增强生成（Augmented Generation）——把片段拼进 Prompt，让 LLM"带资料回答"

RAG 是企业落地最常见架构——成本低、更新快、可溯源。
比微调更适合"知识频繁更新 + 要求可解释"的场景。

十一、MLOps 7 步流水线实战示例

案例：客服 AI 助手的 7 步

步骤 1：用例识别

  • 场景：客服响应慢（30 分钟平均）
  • 目标：降到 5 分钟
  • 指标：响应时长 + 解决率

步骤 2：数据工程

  • 历史客服对话：10 万条
  • 标注：哪些对话被解决 / 没解决
  • 切分：训练 7 / 验证 1 / 测试 2

步骤 3：模型开发

  • 基线：BERT 中文
  • 优化：GPT-4 微调
  • 实验：5 个超参组合，MLflow 追踪

步骤 4：模型评估

  • 测试集准确率：89%
  • 业务指标：响应时长模拟降到 4 分钟
  • 安全：边界测试 100% 通过

步骤 5：模型部署

  • 推理服务：FastAPI + vLLM
  • 网关：Portkey 限流
  • 弹性：K8s 2-10 副本

步骤 6：监控

  • 数据漂移：每周检测
  • 概念漂移：每月检测
  • 性能退化：自动告警

步骤 7：治理

  • 版本化：每个模型 v1.0 / v1.1
  • 文档：自动生成
  • 审计：所有调用留痕

十二、3 个反模式

反模式 1：跳过用例识别直接开做

症状：直接选模型 + 训练。
风险：做出来没人用。
正解：从业务问题开始。

反模式 2：训练集和测试集分布不一致

症状：训练集用老数据，测试集用新数据。
风险：测试集指标高但生产翻车。
正解：用同一时间窗的数据随机切分。

反模式 3：监控只看准确率

症状：只看模型准确率。
风险：业务早变了但模型不知道。
正解：监控业务指标（解决率 / 满意度）。

📖 完整深度论述

本卡对应 Google MLOps + AI 五层技术栈。以下为系统性深度论述。

AI 落地 ≠ 调 API

最大的误解是把"企业 AI 落地"等同于"调一个 LLM API"。真相是：AI 落地是一个完整的系统工程，分五层——数据、模型、编排、服务、治理。企业落地失败的常见原因，正是只做了模型层和服务层，而忽略了数据层和治理层。

这五层的价值在于它澄清了 AI 项目的完整范围。FDE 报价时，客户往往只看到"模型层"（一个 API 调用），而看不到数据层（七成脏活）和治理层（合规安全）的工作量。五层框架是解释"为什么知识库项目要 10-15 万"的有力工具。

MLOps 七步流水线

Google 的 MLOps 实践者指南定义了 AI 落地的标准流水线：

  1. 用例识别与价值定义；
  2. 数据工程（采集/清洗/标注/版本化/切分）；
  3. 模型开发与实验；
  4. 模型评估；
  5. 模型部署；
  6. 监控与持续训练；
  7. 治理与合规。

这七步和传统软件工程的"需求→设计→实现→测试→部署→运维"共享同一骨架，但在"数据"和"模型"这两环多出了独特环节。理解这个映射，FDE 就能复用软件工程的经验，同时识别 AI 特有的挑战。

LLMOps vs MLOps：大模型时代的新增关注点

LLM 时代的 LLMOps 在 MLOps 基础上新增了五个关注点：

  • 微调取代/补充"从零训练"——基础模型已强，无需从零；
  • 实时生成计算——推理延迟和 token 成本成为核心成本项；
  • 向量数据库编排——用于 RAG 检索；
  • 提示工程——Prompt 成为一类新的"代码"；
  • RAG——私有知识接入，无需重训。

这五点直接对应你工作台的方法论："先免费白嫖"（token 成本）、"进厂先找数据"（RAG + 向量库）、"AI 时代顶级能力 = 会提问"（提示工程）。

Gartner 五级成熟度：帮客户定位

Gartner 的 AI 成熟度五级（Awareness → Active → Operational → Systemic → Transformational），是 FDE 帮客户定位的利器：

  • 大多数客户在 2-3 级（试点阶段或刚进生产）；
  • 从 2 级到 3 级的跨越，正是 FDE 的核心价值——把零散试点变成生产流程；
  • 只有 3% 企业达到 5 级（Transformational），说明从"用 AI"到"用好 AI"是巨大鸿沟。

一句话总结：AI 落地是五层系统工程，不是调 API。MLOps 七步是标准流水线，LLMOps 新增 token 成本/RAG/提示工程，Gartner 五级帮客户定位阶段。
