D3 · OpenAI Agent Best Practices

类型：行业权威框架 · 厂商标准
发布：OpenAI（与 Assistants API / Function Calling 配套）
中文卡版本：基于摘要整理 · 2026-09-10

一、定位

OpenAI 是 LLM 商业化最早、最激进的公司。
它的 Agent 最佳实践代表最实用主义的工程路线——
不像 Anthropic 强调 Harness 那么"学院派"，更强调"能跑就上"。

你的方法论「先 Demo 再全案」和 OpenAI 风格很合。
客户问"OpenAI 自己怎么做的"，答案在这。

二、五大核心论点

1. 工具调用（Function Calling）风险分级

OpenAI 把工具按风险分 3 类：

风险 例子 处理
只读 get_weather / search_doc AI 自动
写本地 create_file / send_email AI 自动 + 通知
写外部 transfer_money / delete_account 必须二次确认

实现方式：
- 工具定义时标 requires_confirmation: true
- 用户界面上 Agent 提交后弹"是否确认"
- 用户点确认才执行

对应 A2「生产级 Agent 白皮书」论点 3 + D1「Google 框架」论点 2——三家厂商在这里完全一致。

2. 护栏（Guardrails）从 Prompt 层开始

OpenAI 的护栏先软后硬：

软护栏（Prompt 层）：
- System prompt 写清楚"绝对不能做什么"
- 举反例（"不要告诉用户这个"）
- 用 CoT 让模型先想再做

硬护栏（API 层）：
- Moderation API 检查违规内容
- 自定义过滤器
- 输出再校验（结构 + 范围）

对应 B4「LLM Security」论点 1（内容安全）——

3. 工具调用的循环控制

Agent 死循环是工程大忌。OpenAI 的控制：

控制项 做法
最大步数 超过 N 步强制停止
最大时间 超过 T 秒强制停止
最大 Token 超过预算强制停止
重复检测 同样的工具调用 3 次就停
用户中断 用户随时可以 Cancel

对应 B2「Designing Agentic Systems」论点 2（状态管理）——

4. 评估与测试

OpenAI 推荐的评估做法：

评估类型 工具 频率
单元测试 模型自己评估 + 人工抽样 每次发版
集成测试 跑完整任务流 每次发版
用户反馈 👍👎 + 文字反馈 持续
离线对比 A/B 不同 Prompt / 模型 每周

核心指标：
- 任务成功率
- 平均对话轮数
- Token 成本
- 用户满意度

对应 A3 + D1 的评估体系——

5. Agent + RAG 协同

OpenAI 的"标准组合"：

用户问题
  ↓
[Agent 大脑]
  ↓ 决定要不要查
  ↓
[RAG 检索] → [向量数据库]
  ↓ 召回 Top-K
[Agent 大脑]
  ↓ 整合信息 + 生成
[回答 + 引用]

关键设计：
- Agent 不是直接调 LLM，是"Agent = LLM + 工具 + 记忆 + 规划"
- RAG 是 Agent 的一个工具，不是替代 Agent
- Agent 决定"要不要查、查几次、查什么"

对应 B3「RAG in Action」+ B2「Designing Agentic Systems」——

十一、Function Calling 完整代码示例

Python + OpenAI Function Calling

import openai
import json

# 1. 定义工具（白名单）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_order_status",
            "description": "查询订单状态",
            "tier": "L0",  # 只读，自动
            "parameters": {
                "type": "object",
                "properties": {
                    "order_id": {"type": "string", "description": "订单 ID"}
                },
                "required": ["order_id"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "refund_order",
            "description": "退款订单",
            "tier": "L3",  # 高危写，需人工确认
            "requires_confirmation": True,
            "max_amount": 1000,
            "parameters": {
                "type": "object",
                "properties": {
                    "order_id": {"type": "string"},
                    "amount": {"type": "number", "maximum": 1000},
                    "reason": {"type": "string"}
                },
                "required": ["order_id", "amount", "reason"]
            }
        }
    }
]

# 2. 调用 LLM
response = openai.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "订单 12345 现在什么状态？"}],
    tools=tools
)

# 3. 检查是否要调用工具
if response.choices[0].message.tool_calls:
    for tool_call in response.choices[0].message.tool_calls:
        tool_name = tool_call.function.name
        tool_args = json.loads(tool_call.function.arguments)

        # 4. 风险检查
        tool_def = next(t for t in tools if t['function']['name'] == tool_name)
        if tool_def['function'].get('tier', 'L0') >= 'L3':
            if not human_confirmed(tool_name, tool_args):
                return require_human_confirmation(tool_name, tool_args)

        # 5. 执行工具
        result = execute_tool(tool_name, tool_args)

        # 6. 把结果回传给 LLM
        response = openai.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "user", "content": "订单 12345 现在什么状态？"},
                response.choices[0].message,
                {"role": "tool", "tool_call_id": tool_call.id, "content": result}
            ]
        )

十二、4 个反模式

反模式 1：把"should_call_tool"放在 Prompt

症状：「请只在需要时调用 get_order_status」写在 prompt。
风险：模型可能误调用。
正解：用工具的 tier 强制约束（不在白名单的拒绝）。

反模式 2：忽略 tier

症状：所有工具都自动调用。
风险：高危工具被 AI 误用。
正解：按 tier 强制 L0-L4 处理。

反模式 3：循环控制缺失

症状：模型可以无限循环调工具。
风险：Token 爆炸 + 死循环。
正解：max_steps + max_time + 重复检测。

反模式 4：结果不验证

症状：工具返回后直接交给模型。
风险：错误数据被模型当成真。
正解：结果 schema 校验 + 异常告警。
