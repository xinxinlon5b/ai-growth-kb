---## 1. 完整规范的函数调用

1.1 定义

"Function calling provides a way to connect Large Language Models to external tools and APIs. The model generates a JSON object describing which function to call and with what arguments, rather than generating a direct text response."

函数调用提供了一种将大型语言模型连接到外部工具和 API 的方法。模型生成一个 JSON 对象，描述要调用哪个函数以及使用什么参数，而不是生成直接的文本响应。

1.2 工作流程

  1. 定义工具：以 JSON schema 声明可用函数
  2. 模型决定调用：LLM 决定调哪个函数、传什么参数
  3. 执行函数：你的代码执行实际函数
  4. 回传结果：把结果回传给 LLM
  5. 生成响应：LLM 基于结果生成最终响应

1.3 Function 定义 Schema

json { "type": "function", "function": { "name": "get_weather", "description": "Get the current weather in a given location", "parameters": { "type": "object", "properties": { "location": { "type": "string", "description": "The city and country, e.g. 'Beijing, China'" }, "unit": { "type": "string", "enum": ["celsius", "fahrenheit"], "description": "The temperature unit" } }, "required": ["location"] } } }## 2.3 风险分级三级

2.1 只读工具（Read-Only）

"Read-only tools that don't modify any state, such as get_weather, search_documents, list_items. These can be safely executed automatically by the agent."

只读工具不修改任何状态，如 get_weather、search_documents、list_items。这些可以由代理安全地自动执行。

2.2 本地写工具（Local Write）

"Tools that modify local state, such as create_file, update_record, send_email_draft. These can be executed automatically but should log the action for audit."

修改本地状态的工具，如 create_file、update_record、send_email_draft。这些可以自动执行，但应记录该操作以供审计。

2.3 外部写工具（External Write）

"Tools that affect external systems, such as transfer_money, delete_account, send_real_email. These require explicit human confirmation before execution."

影响外部系统的工具，如 transfer_money、delete_account、send_real_email。这些在执行前需要明确的人工确认。## 3. 托管代理（Managed Agents）

3.1 定义

"Managed Agents is a managed service for deploying AI agents in production with built-in safety, observability, and scale. It handles the infrastructure concerns so you can focus on the agent's logic."

Managed Agents 是一项托管服务，用于在生产环境中部署 AI 代理，具有内置安全性、可观测性和可扩展性。它处理基础设施问题，因此您可以专注于代理的逻辑。

3.2 核心能力

  • 内置 Guardrails：输入过滤、输出过滤、动作约束
  • 完整 Trace：每个调用可追溯
  • 自动扩缩：根据负载自动调整资源
  • 风险分级 + 人工接管：高危操作需确认
  • 审计日志：所有动作记录
  • A/B 测试：支持流量分割

3.3 部署模式

  • 影子部署：新旧模型并行，不产生实际影响
  • 金丝雀发布：5% → 25% → 50% → 100%
  • 蓝绿部署：并行运行两个版本，切换流量
  • A/B 测试：对比两个版本## 4. 结构化输出

4.1 定义

"Structured Outputs is a feature that ensures the model always generates responses that match your supplied JSON Schema. This is useful for reliably generating structured data and building agent workflows that depend on parsed outputs."

Structured Outputs 是一项功能，确保模型始终生成与您提供的 JSON Schema 匹配的响应。这对于可靠地生成结构化数据和构建依赖于解析输出的代理工作流非常有用。

4.2 使用方式

```python
from pydantic import BaseModel
from openai import OpenAI

class WeatherResponse(BaseModel):
location: str
temperature: float
unit: str

client = OpenAI()
response = client.chat.completions.create(
model="gpt-4o",
messages=[{"role": "user", "content": "What's the weather in Beijing?"}],
response_format=WeatherResponse
)
```## 5. 客户引用话术
