核心模式详细定义

1. Bounded Context（限界上下文）

"A description of a boundary (typically a subsystem, or the work of a particular team) within which a particular model is defined and applicable."

限界上下文是特定模型被定义和适用的边界（通常是子系统或特定团队的工作）的描述。

2. Ubiquitous Language（统一语言）

"A language structured around the domain model and used by all team members to connect all the activities of the team with the software."

统一语言是一种围绕领域模型构建的语言，由所有团队成员使用，将团队的所有活动与软件连接起来。

3. Continuous Integration（持续集成）

"A process that keeps a software system in a working state by frequently merging and testing all changes to the system."

持续集成是通过频繁合并和测试系统的所有更改来保持软件系统处于工作状态的过程。

4. Model-Driven Design（模型驱动设计）

"An approach to software development that emphasizes the use of domain models as the primary artifacts of software development."

模型驱动设计是一种强调使用领域模型作为软件开发的主要工件的软件开发方法。

5. Hands-on Modelers（亲手建模者）

"Developers who are actively involved in the modeling process and have a deep understanding of the domain."

亲手建模者是积极参与建模过程并对领域有深入理解的开发人员。

6. Refactoring Toward Deeper Insight（重构以获得更深洞察）

"The process of changing a software system in such a way that it does not change the behavior of the code, but improves its internal structure, with the goal of gaining a deeper understanding of the domain."

重构以获得更深洞察是以不改变代码行为但改进其内部结构的方式改变软件系统的过程，目的是获得对领域的更深理解。

7. Layered Architecture（分层架构）

"A pattern that separates the concerns of the application into layers: User Interface, Application, Domain, and Infrastructure."

分层架构是将应用程序的关注点分离为层的模式：用户界面、应用程序、域和基础设施。

8. Entities（实体）

"An object that is defined by its identity, rather than its attributes. An entity has its own life cycle within the system."

实体是由其身份而不是其属性定义的对象。实体在系统内有自己的生命周期。

9. Value Objects（值对象）

"An object that is defined by its attributes, rather than its identity. Value objects are immutable."

值对象是由其属性而不是其身份定义的对象。值对象是不可变的。

10. Domain Events（领域事件）

"An event that is significant to the domain, often used to communicate changes between bounded contexts."

领域事件是对领域具有重要意义的事件，通常用于在限界上下文之间传达更改。

11. Services（服务）

"An object that performs a significant business function that does not naturally fit into an entity or value object."

服务是执行不属于实体或值对象的显著业务功能的对象。

12. Modules（模块）

"A way of organizing related concepts within a model. Modules are used to group related classes and to define the relationships between them."

模块是在模型中组织相关概念的方式。模块用于对相关类进行分组并定义它们之间的关系。

13. Aggregates（聚合）

"A cluster of domain objects that can be treated as a single unit for the purpose of data changes. An aggregate has a root and a boundary."

聚合是可以作为单个单元进行数据更改的域对象集群。聚合具有根和边界。

14. Repositories（仓储）

"A mechanism for encapsulating storage, retrieval, and search behavior for objects in a domain. A repository acts like a collection of objects in memory."

仓储是一种封装域对象的存储、检索和搜索行为的机制。仓储的行为类似于内存中的对象集合。#### 15. Factories（工厂）

"A mechanism for encapsulating the creation of complex objects and aggregates, ensuring that the resulting object is in a valid state."

工厂是一种封装复杂对象和聚合创建的机制，确保生成的对象处于有效状态。

Context Map（上下文映射）

"A document that describes the relationships between bounded contexts and the ways in which they integrate with each other."

上下文映射是描述限界上下文之间关系以及它们彼此集成方式的文档。

Partnership（伙伴关系）

"A relationship between two bounded contexts in which the teams responsible for each context collaborate to integrate their systems."

伙伴关系是两个限界上下文之间的关系，其中每个上下文负责的团队协作以集成其系统。

Shared Kernel（共享内核）

"A subset of the domain model that two teams agree to share. The shared kernel is kept small to minimize coupling."

共享内核是两个团队同意共享的领域模型的子集。共享内核保持较小以最小化耦合。

Customer/Supplier Development（客户/供应商开发）

"A relationship between two bounded contexts in which one (the customer) depends on the other (the supplier) for a service. The customer's needs drive the supplier's priorities."

客户/供应商开发是两个限界上下文之间的关系，其中一个（客户）依赖另一个（供应商）提供的服务。客户的需求驱动供应商的优先级。

Conformist（跟随者）

"A relationship between two bounded contexts in which one context conforms to the model of the other, without any translation layer."

跟随者是两个限界上下文之间的关系，其中一个上下文遵循另一个的模型，没有任何翻译层。

Anticorruption Layer（防腐层）

"A layer that translates between two bounded contexts, preventing the model of one context from being corrupted by the model of the other."

防腐层是两个限界上下文之间的翻译层，防止一个上下文的模型被另一个上下文的模型破坏。

Open-Host Service（开放主机服务）

"A service that exposes a protocol for accessing a system, where the protocol is open to other systems and is treated as a public API."

开放主机服务是公开访问系统的协议的服务，其中协议对其他系统开放并被视为公共 API。

Published Language（发布语言）

"A well-known, shared language used for communication between bounded contexts. The published language serves as a lingua franca for integration."

发布语言是用于限界上下文之间通信的广为人知的共享语言。发布语言充当集成的通用语。

Separate Ways（各行其道）

"A decision to not integrate two bounded contexts, and to accept the duplication of functionality that this entails."

各行其道是不集成两个限界上下文并接受由此产生的功能重复的决定。

Big Ball of Mud（大泥球）

"A system that lacks a coherent architecture, with tangled dependencies and no clear boundaries. Big Ball of Mud is the natural state of most software systems, and DDD provides tools to manage this complexity."

大泥球是缺乏连贯架构的系统，依赖关系纠缠，没有明确的边界。大泥球是大多数软件系统的自然状态，DDD 提供了管理这种复杂性的工具。> "A relationship between two bounded contexts in which one (the customer) depends on the other (the supplier) for a service. The customer's needs drive the supplier's priorities."

Core Domain（核心域）

"The part of the domain that is most important to the organization and that provides the greatest competitive advantage."

核心域是域中对组织最重要并提供最大竞争优势的部分。

Generic Subdomains（通用子域）

"Parts of the domain that are necessary but not central to the organization's competitive advantage. Generic subdomains can often be outsourced or replaced with off-the-shelf solutions."

通用子域是必要但不属于组织竞争优势的域部分。通用子域通常可以外包或用现成的解决方案替换。

Domain Vision Statement（域愿景声明）

"A short document that describes the core domain and the value it provides to the组织。The domain vision statement helps align the team around the most important parts of the domain."

域愿景声明是一个简短的文档，描述核心域及其为组织提供的价值。域愿景声明帮助团队围绕域的最重要部分保持一致。

Highlighted Core（突出核心）

"A technique for drawing attention to the core domain by separating it from the rest of the application and making it a focal point for the development effort."

突出核心是一种通过将核心域与应用程序的其余部分分离并使其成为开发工作的焦点来引起对核心域注意的技术。

Cohesive Mechanisms（内聚机制）

"A pattern that identifies the most important parts of the core domain and provides a cohesive set of abstractions to support them."

内聚机制是一种识别核心域最重要部分并提供一组内聚抽象来支持它们的模式。

Segregated Core（隔离核心）

"A pattern that separates the core domain from the supporting infrastructure, making it easier to focus on the most important parts of the system."

隔离核心是一种将核心域与支持基础设施分离的模式，使其更容易关注系统最重要的部分。

Abstract Core（抽象核心）

"A pattern that identifies the most fundamental concepts of the core domain and represents them as abstractions, making it easier to reuse and evolve the core domain."

抽象核心是一种识别核心域最基本的概念并将它们表示为抽象的模式，使其更容易重用和发展核心域。### 大规模结构模式

Evolving Order（演进秩序）

"一种允许大型系统的结构随着时间演进的模式，无需前期的大设计。结构被允许在构建系统时出现。"

演进秩序是一种允许大型系统的结构随着时间演进的模式，无需前期的大设计。结构被允许在构建系统时出现。

System Metaphor（系统隐喻）

"一种使用熟悉的类比来描述软件系统结构的模式。系统隐喻帮助团队成员以一致的方式理解系统。"

系统隐喻是一种使用熟悉的类比来描述软件系统结构的模式。系统隐喻帮助团队成员以一致的方式理解系统。

Responsibility Layers（责任层）

"一种将大型系统的结构组织为层次的模式，每个层次都有明确的职责。责任层有助于管理系统不同部分之间的依赖关系。"

责任层是一种将大型系统的结构组织为层次的模式，每个层次都有明确的职责。责任层有助于管理系统不同部分之间的依赖关系。

Knowledge Level（知识级别）

"一种将处于相同知识或抽象级别的对象组合在一起的模式。知识级别通过提供清晰的详细程度级别来帮助管理域的复杂性。"

知识级别是一种将处于相同知识或抽象级别的对象组合在一起的模式。知识级别通过提供清晰的详细程度级别来帮助管理域的复杂性。

Pluggable Component Framework（可插拔组件框架）
