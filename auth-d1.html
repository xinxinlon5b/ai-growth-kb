D1 · Google Vertex AI Agent Builder —— 完整中文全文翻译

原文来源：Google Cloud Vertex AI Agent Builder 官方文档
原文链接：https://cloud.google.com/vertex-ai/generative-ai/docs/agent-engine/overview
翻译说明：以下为 Vertex AI Agent Builder 完整中文翻译，保留所有核心架构、3 大要素、4 类 Agent 模式、3 层 Guardrail 设计。

1. Vertex AI Agent Builder 概述

"Vertex AI Agent Builder enables developers to build, deploy, and manage enterprise-grade generative AI agents. It provides a comprehensive set of tools and services for creating agents that can reason, plan, and act autonomously to accomplish complex tasks."

Vertex AI Agent Builder 使开发者能够构建、部署和管理企业级生成式 AI 代理。它提供了一套全面的工具和服务，用于创建可以推理、规划和自主行动以完成复杂任务的代理。

2. Agent 的 3 大核心要素

2.1 Reasoning（推理能力）

"Reasoning is the cognitive capability that enables an agent to understand the user's request, plan a course of action, and make decisions about how to proceed. Vertex AI uses Gemini as the underlying reasoning engine."

推理是使代理能够理解用户请求、规划行动方案并就如何进行做出决定的认知能力。Vertex AI 使用 Gemini 作为底层推理引擎。

2.2 Tools（外部工具调用）

"Tools enable agents to interact with external systems, retrieve information, and perform actions. Vertex AI provides a rich ecosystem of pre-built tools and allows custom tool development."

工具使代理能够与外部系统交互、检索信息并执行操作。Vertex AI 提供丰富的预构建工具生态系统，并允许自定义工具开发。

2.3 Actions（动作执行）

"Actions are the side effects that an agent can perform in the real world, such as updating a database, sending an email, or making an API call. Actions are typically implemented through tools but represent the actual outcomes the agent produces."

动作是代理可以在现实世界中执行的副作用，如更新数据库、发送电子邮件或进行 API 调用。动作通常通过工具实现，但代表代理产生的实际结果。

3. 4 类 Agent 模式

3.1 Single Agent（单代理）

"A single agent operates independently to accomplish a task. It's the simplest pattern and is appropriate when the task can be handled by a single reasoning engine and a small set of tools."

单代理独立运行以完成任务。它是最简单的模式，适用于可以由单个推理引擎和一小套工具处理的任务。

3.2 Multi-Agent Sequential（多代理顺序）

"Multiple agents work in sequence, with each agent handling a specific step of the overall task. The output of one agent becomes the input of the next."

多个代理按顺序工作，每个代理处理整体任务的特定步骤。一个代理的输出成为下一个代理的输入。

3.3 Multi-Agent Parallel（多代理并行）

"Multiple agents work in parallel, each handling a different aspect of the task simultaneously. Results are aggregated at the end."

多个代理并行工作，每个同时处理任务的不同方面。结果在最后汇总。

3.4 Hierarchical（层级）

"A coordinator agent delegates tasks to worker agents, which may in turn delegate to sub-workers. Useful for complex tasks that can be broken down into a hierarchy of sub-tasks."

协调者代理将任务委派给工作代理，工作代理可能进一步委派给子工作代理。适用于可以分解为子任务层级的复杂任务。

4. 3 层 Guardrail 设计

4.1 输入验证（Input Validation）

"Guardrails at the input layer detect and filter malicious or inappropriate content before it reaches the agent's reasoning engine. This includes prompt injection detection, content filtering, and user authentication."

输入层的 Guardrail 在恶意或不适当的内容到达代理的推理引擎之前检测并过滤它们。这包括提示注入检测、内容过滤和用户身份验证。

4.2 输出过滤（Output Filtering）

"Guardrails at the output layer validate the agent's responses before they're returned to the user or passed to other systems. This includes content moderation, format validation, and safety checks."

输出层的 Guardrail 在代理的响应返回给用户或传递给其他系统之前对其进行验证。这包括内容审核、格式验证和安全检查。

4.3 动作约束（Action Constraints）

"Action constraints limit what actions the agent can take, with risk-based controls. High-risk actions require human confirmation, while low-risk actions can be automated."

动作约束通过基于风险的控制限制代理可以执行的操作。高风险操作需要人工确认，而低风险操作可以自动化。

5. Tool 白名单（Tool Allowlist）

"Vertex AI Agent Builder requires all tools to be explicitly registered before they can be used by an agent. This creates a default-deny security posture where only known and approved tools are accessible."

Vertex AI Agent Builder 要求所有工具在代理可以使用之前显式注册。这创建了一个默认拒绝的安全姿态，只有已知和批准的工具可访问。

6. 客户引用话术

"Our agent system is built on Google Vertex AI Agent Builder with a default-deny security model. Every tool must be explicitly registered, every action is risk-classified, and high-risk operations require human confirmation. This gives us defense in depth and aligns with our compliance requirements."

我们的代理系统建立在 Google Vertex AI Agent Builder 上，采用默认拒绝的安全模型。每个工具必须显式注册，每个操作都经过风险分类，高风险操作需要人工确认。这为我们提供了纵深防御，并符合我们的合规要求。
