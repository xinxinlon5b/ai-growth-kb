---## 一、SWEBOK V4（IEEE 软件工程知识体系）

1.1 概述

"The IEEE Computer Society's Guide to the Software Engineering Body of Knowledge (SWEBOK Guide) V4 identifies 15 knowledge areas (KAs) of the generally accepted and accepted software engineering knowledge."

IEEE 计算机学会的《软件工程知识体系指南》（SWEBOK Guide）V4 识别了 15 个公认和接受的软件工程知识领域（KAs）。

1.2 15 大知识域

  1. Software Requirements（软件需求）
  2. Software Design（软件设计）
  3. Software Construction（软件构造）
  4. Software Testing（软件测试）
  5. Software Maintenance（软件维护）
  6. Software Configuration Management（软件配置管理）
  7. Software Engineering Management（软件工程管理）
  8. Software Engineering Process（软件工程过程）
  9. Software Engineering Models and Methods（软件工程模型和方法）
  10. Software Quality（软件质量）
  11. Software Engineering Professional Practice（软件工程专业实践）
  12. Software Engineering Economics（软件工程经济学）
  13. Computing Foundations（计算基础）
  14. Mathematical Foundations（数学基础）
  15. Engineering Foundations（工程基础）

1.3 每个知识域的核心内容

Software Requirements（软件需求）

"Software requirements express the needs and constraints placed on a software product that contribute to the solution of some real-world problem."

软件需求表达了对软件产品的需求和约束，有助于解决一些现实世界的问题。

Software Design（软件设计）

"Software design is the process of defining the architecture, components, interfaces, and other characteristics of a system or component."

软件设计是定义系统或组件的架构、组件、接口和其他特征的过程。

Software Testing（软件测试）

"Software testing is the verification of a software product's behavior through execution, observation, and analysis of the product under test."

软件测试是通过执行、观察和分析被测产品来验证软件产品行为的过程。

Software Construction（软件构造）

"Software construction refers to the detailed creation of working software through coding, verification, unit testing, integration testing, and debugging."

软件构造是指通过编码、验证、单元测试、集成测试和调试来详细创建工作软件的过程。## 二、ISO/IEC/IEEE 12207:2017（软件生命周期过程）

2.1 概述

"ISO/IEC/IEEE 12207:2017 establishes a common framework for software life cycle processes, with well-defined terminology, that can be referenced by the software industry."

ISO/IEC/IEEE 12207:2017 为软件生命周期过程建立了公共框架，具有明确定义的术语，可供软件行业参考。

2.2 四大过程组

协议过程（Agreement Processes）

  • 获取过程（Acquisition Process）
  • 供应过程（Supply Process）

组织项目使能过程（Organization-Project Enabling Processes）

  • 基础设施管理（Infrastructure Management）
  • 项目组合管理（Project Portfolio Management）
  • 人力资源管理（Human Resource Management）
  • 质量管理（Quality Management）

技术管理过程（Technical Management Processes）

  • 项目规划（Project Planning）
  • 项目评估和控制（Project Assessment and Control）
  • 决策管理（Decision Management）
  • 风险管理（Risk Management）
  • 配置管理（Configuration Management）
  • 信息管理（Information Management）
  • 度量（Measurement）
  • 质量保证（Quality Assurance）

技术过程（Technical Processes）

  • 业务或任务分析（Business or Mission Analysis）
  • 利益相关者需求定义（Stakeholder Needs and Requirements Definition）
  • 系统/软件需求分析（System/Software Requirements Analysis）
  • 架构定义（Architecture Definition）
  • 实现（Implementation）
  • 集成（Integration）
  • 验证（Verification）
  • 确认（Validation）
  • 转移（Transition）
  • 操作（Operation）
  • 维护（Maintenance）
  • 处置（Disposal）## 三、DORA 四个关键指标（DORA Four Keys）

DORA 的研究确定了衡量软件交付绩效的四个关键指标。这些指标已被全球数千个组织采用，以衡量和改进其软件交付能力。

DORA 的研究确定了衡量软件交付绩效的四个关键指标。这些指标已被全球数千个组织采用，以衡量和改进其软件交付能力。

3.1 部署频率（Deployment Frequency）

组织成功将变更发布到生产的频率。高性能团队按需部署，每天多次。

组织成功将变更发布到生产的频率。高性能团队按需部署，每天多次。

3.2 变更前置时间（Lead Time for Changes）

从代码提交到代码成功在生产中运行所需的时间。高性能团队的前置时间不到一天。

从代码提交到代码成功在生产中运行所需的时间。高性能团队的前置时间不到一天。

3.3 变更失败率（Change Failure Rate）

导致服务降级或需要修复的变更百分比。高性能团队的变更失败率为 0-15%。

导致服务降级或需要修复的变更百分比。高性能团队的变更失败率为 0-15%。

3.4 恢复服务时间（Time to Restore Service）

当发生服务事件时恢复服务所需的时间。高性能团队可以在不到一小时内恢复服务。

当发生服务事件时恢复服务所需的时间。高性能团队可以在不到一小时内恢复服务。## 四、Gang of Four 设计模式（23 种）

"Design Patterns: Elements of Reusable Object-Oriented Software (1994) by Gamma, Helm, Johnson, and Vlissides (the 'Gang of Four') cataloged 23 classic design patterns organized into three categories: Creational, Structural, and Behavioral."

《设计模式：可复用面向对象软件的基础》（1994）由 Gamma、Helm、Johnson 和 Vlissides（"四人帮"）编目了 23 种经典设计模式，分为三类：创建型、结构型和行为型。

4.1 创建型模式（Creational Patterns）

  1. Abstract Factory（抽象工厂）
  2. Builder（建造者）
  3. Factory Method（工厂方法）
  4. Prototype（原型）
  5. Singleton（单例）

4.2 结构型模式（Structural Patterns）

  1. Adapter（适配器）
  2. Bridge（桥接）
  3. Composite（组合）
  4. Decorator（装饰器）
  5. Facade（外观）
  6. Flyweight（享元）
  7. Proxy（代理）

4.3 行为型模式（Behavioral Patterns）

  1. Chain of Responsibility（责任链）
  2. Command（命令）
  3. Interpreter（解释器）
  4. Iterator（迭代器）
  5. Mediator（中介者）
  6. Memento（备忘录）
  7. Observer（观察者）
  8. State（状态）
  9. Strategy（策略）
  10. Template Method（模板方法）
  11. Visitor（访问者）## 翻译附记
