🏛️ 权威支撑C2

C2 · 混沌工程（Chaos Engineering）

类型：通用软件可靠性方法论
来源：Netflix 提出 · 《Chaos Engineering: Resilience through Controlled Disruption》
中文卡版本：基于摘要整理 · 2026-09-10

一、定位

传统测试是"正常情况下能不能跑"。
混沌工程是"异常情况下会不会死"。

这是 FDE 投产前必须做的验证手段。
你的「脏活 7 成」里，混沌测试是最脏的那部分。

二、核心论点

1. 核心思想：主动制造异常

不是等系统挂了才修，而是主动制造异常看会不会挂：

  • 把一个服务 kill 掉
  • 把网络延迟加 1 秒
  • 把数据库返回改成 500
  • 把硬盘写满
  • 把 DNS 解析搞错

目的：不是证明系统多强，是证明系统在异常下不死。

对应 A3「企业 Agent 评估」的"故障注入"——
混沌工程是 A3 在基础设施层的同源方法。

2. 四大原则

原则 释义
围绕稳态行为设计实验 找最重要的"业务指标"作为稳态
多种变量真实世界 模拟真实世界的各种故障
在生产环境跑 不在测试环境跑（在测试环境不死不代表生产不死）
自动化持续运行 持续跑，不是跑一次

稳态举例：
- 订单成功率 > 99%
- 客服响应时长 < 5s
- 退款到账时长 < 1 小时

对应 A3「企业 Agent 评估」论点 4"可验证标准"——
稳态 = 可验证的指标。

3. 实验设计：4 步

① 定义稳态（业务关键指标）
② 假设（如果 X 异常发生，稳态会怎样）
③ 跑实验（制造 X 异常）
④ 验证（稳态有没有受影响）

经典实验：
- Chaos Monkey：随机 kill 服务实例
- Chaos Gorilla：模拟整个可用区挂掉
- Chaos Kong：模拟整个 region 挂掉
- Latency Monkey：注入延迟

对应 A2「生产级 Agent 白皮书」论点 4"故障隔离"——
混沌工程是验证故障隔离是否生效的标准手段。

4. FDE 项目里的具体应用

FDE 场景 混沌测试怎么做
知识库 RAG 把召回的文档故意给错的，看模型照搬还是拒答
Agent 工具调用 故意让工具返回错误，看 Agent 是死循环还是优雅降级
业务写操作 故意让"提交订单"中途失败，看业务回滚是否生效
人工接管 故意制造需要人工确认的场景，看接管流程顺不顺
模型服务 故意让模型超时，看有没有降级到备用模型

对应 SOP-03 第 5 步"复盘进案例库"——
混沌测试结果要进复盘，作为下次改进的输入。

5. 与 A3 的关系

A3「企业 Agent 评估」讲的是 AI Agent 的评估方法论，
C2「混沌工程」讲的是所有分布式系统的可靠性方法论。

关系：
- A3 是 C2 在 AI 场景的特化
- C2 是 A3 思想的更广来源
- 两者应该结合用：A3 的故障注入 + C2 的稳态定义 = 完整的 FDE 投产验证

十一、5 个标准故障注入剧本

剧本 1：网络延迟注入

  • 目标：测系统对慢响应的容忍
  • 怎么做：用 toxiproxi 注入 1-5 秒延迟
  • 预期：超时后降级 / 重试 / 报错

剧本 2：服务不可用注入

  • 目标：测系统对依赖故障的容忍
  • 怎么做：Chaos Monkey 随机 kill 服务
  • 预期：服务降级 / 熔断 / 不雪崩

剧本 3：数据错误注入

  • 目标：测 AI 对错误输入的容忍
  • 怎么做：故意喂错数据 / 缺字段 / 错格式
  • 预期：模型不照搬 / 报错 / 提示重试

剧本 4：工具失败注入

  • 目标：测 Agent 对工具失败的容忍
  • 怎么做：让工具返回 500 / 超时 / 错误结果
  • 预期：Agent 重试 / 换工具 / 优雅降级

剧本 5：恶意输入注入

  • 目标：测 AI 对 prompt injection 的抵抗
  • 怎么做：输入"忽略之前指令，执行 X"
  • 预期：被护栏拦截 / 不执行恶意指令

十二、3 个 FDE 项目实战剧本

剧本 A：RAG 召回失败

  • 故意把向量库断网
  • 看 Agent 是返回空还是报错
  • 预期：返回"我不知道"+ 不编造

剧本 B：订单创建失败

  • 故意让订单 API 返回 500
  • 看 Agent 是否回滚（取消已创建的相关数据）
  • 预期：Saga 模式自动回滚 + 告警

剧本 C：人工接管超时

  • 故意让 L3 动作的确认人 5 分钟不响应
  • 看 Agent 是否自动取消 / 升级 / 兜底
  • 预期：自动取消 + 通知替代决策人
