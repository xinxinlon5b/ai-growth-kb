C1 · MLOps 成熟度模型

MLOps 定义 (Machine Learning Operations)
将 DevOps 原则应用于机器学习系统的工程实践。[SOP: 部署阶段、运维阶段、迭代阶段]
[⭐⭐⭐⭐] [业界实践]

CDSO MLOps 成熟度模型
Microsoft Azure 团队提出的 0-5 级 MLOps 成熟度模型。
[⭐⭐⭐⭐] [Microsoft CDSO]

MLOps Level 0 (无 MLOps)
Jupyter Notebook + 手工部署，无自动化。适合早期实验。
[⭐⭐⭐] [Microsoft CDSO]

MLOps Level 1 (DevOps 但无 ML)
有 CI/CD 流水线但模型仍手工管理。
[⭐⭐⭐] [Microsoft CDSO]

MLOps Level 2 (自动化训练)
训练流水线自动化，模型可重现。
[⭐⭐⭐] [Microsoft CDSO]

MLOps Level 3 (模型部署自动化)
模型可自动部署到多环境。
[⭐⭐⭐] [Microsoft CDSO]

MLOps Level 4 (全 MLOps)
CI/CD + CT（Continuous Training），自动再训练。
[⭐⭐⭐] [Microsoft CDSO]

MLOps Level 5 (智能 MLOps)
含 AIOps 与元学习的高级阶段。
[⭐⭐⭐] [Microsoft CDSO]

MLOps 三大支柱
数据工程、模型工程、运维工程。
[⭐⭐⭐] [业界实践]

CT (Continuous Training, 持续训练)
MLOps 特有：基于新数据自动触发模型再训练。
[⭐⭐⭐] [业界实践]

CT vs CI/CD
CI/CD 关注代码变更，CT 关注数据变更与性能漂移。
[⭐⭐⭐] [业界实践]

MLOps 流水线工具
Kubeflow、MLflow、TFX、Airflow、Metaflow、ZenML、BentoML。
[⭐⭐⭐] [MLOps]

MLflow
Databricks 开源的 ML 生命周期管理平台，含 Tracking、Projects、Models、Registry。
[⭐⭐⭐] [Databricks]

Kubeflow
Kubernetes 之上的 ML 工作流平台。
[⭐⭐⭐] [CNCF]

TFX (TensorFlow Extended)
Google 端到端 ML 流水线框架。
[⭐⭐⭐] [Google]

Feast (Feature Store)
Linux Foundation 的开源特征存储。
[⭐⭐⭐] [Linux Foundation]

BentoML
模型打包与服务化框架。
[⭐⭐⭐] [Yelp]

模型打包 (Model Packaging)
将模型 + 依赖打包为可部署单元：Docker、SavedModel、ONNX。
[⭐⭐⭐] [MLOps]

模型服务化 (Model Serving)
将模型部署为可调用的服务：REST、gRPC、批处理、流式。
[⭐⭐⭐] [MLOps]

模型推理模式 (Inference Modes)
在线推理（同步）、离线推理（批）、流式推理。
[⭐⭐⭐] [MLOps]

模型监控 (Model Monitoring)
对模型的输入分布、输出分布、性能、漂移的持续监控。
[⭐⭐⭐] [MLOps]

C3 · RAG 系统工程

RAG 完整生命周期
数据准备 → 索引构建 → 查询处理 → 检索 → 重排 → 生成 → 评估 → 监控。
[⭐⭐⭐] [RAG 工程]

文档加载 (Document Loading)
从 PDF、Word、HTML、Markdown、Notion、Slack 等加载数据。
[⭐⭐⭐] [LangChain]

文档解析 (Document Parsing)
将原始文档解析为结构化内容：Unstructured.io、LlamaParse。
[⭐⭐⭐] [RAG 工程]

文本分块 (Text Chunking)
将长文档拆分为适合嵌入的小段：固定大小、句子、段落、语义、递归。
[⭐⭐⭐] [LangChain]

Chunk 大小选择
权衡：太大精度低、检索召回少；太小语义不完整。
[⭐⭐⭐] [RAG 工程]

Chunk 重叠 (Chunk Overlap)
相邻 chunk 重叠部分文本以保留上下文。
[⭐⭐⭐] [RAG 工程]

嵌入生成 (Embedding Generation)
使用 Embedding 模型将 chunk 转为向量。
[⭐⭐⭐] [RAG 工程]

向量索引 (Vector Index)
将向量组织为可高效查询的结构：HNSW、IVF、Flat。
[⭐⭐⭐] [RAG 工程]

相似度度量 (Similarity Metrics)
余弦相似度、欧氏距离、点积、曼哈顿距离。
[⭐⭐⭐] [RAG 工程]

top-k 检索 (Top-K Retrieval)
返回相似度最高的 k 个结果。
[⭐⭐⭐] [RAG 工程]

MMR (Maximal Marginal Relevance)
Carbonell & Goldstein 1998：相关性 + 多样性的检索结果排序。
[⭐⭐⭐] [RAG 工程]

元数据过滤 (Metadata Filtering)
基于文档元数据（时间、作者、类型）的预过滤。
[⭐⭐⭐] [RAG 工程]

混合搜索 (Hybrid Search)
向量搜索 + BM25 关键词搜索的加权融合。
[⭐⭐⭐] [RAG 工程]

Cross-Encoder Reranking
使用 Cross-Encoder 对候选文档重新排序：Cohere Rerank、BGE Reranker。
[⭐⭐⭐] [RAG 工程]

Cohere Rerank 3
Cohere 2024 发布的商用重排序模型。
[⭐⭐⭐] [Cohere]

查询理解 (Query Understanding)
意图识别、实体提取、查询改写、HyDE。
[⭐⭐⭐] [RAG 工程]

上下文压缩 (Contextual Compression)
对检索结果进行压缩以节省 token：LLMLingua、LongLLMLingua。
[⭐⭐⭐] [RAG 工程]

RAG 评估指标 (RAG Metrics)
Context Precision、Context Recall、Faithfulness、Answer Relevancy。
[⭐⭐⭐] [RAGAS]

Faithfulness (忠实度)
生成答案基于检索上下文的程度。
[⭐⭐⭐] [RAGAS]

Answer Relevancy (答案相关性)
生成答案与问题的相关程度。
[⭐⭐⭐] [RAGAS]

Context Precision (上下文精度)
检索结果中相关文档的比例。
[⭐⭐⭐] [RAGAS]

Context Recall (上下文召回率)
所有相关文档被检索到的比例。
[⭐⭐⭐] [RAGAS]

C4 · AgentOps 与智能体工程

AgentOps 定义
将 DevOps/MLOps 原则应用于 AI Agent 的工程实践。
[⭐⭐⭐] [AgentOps 2025]

AgentOps vs MLOps/LLMOps
AgentOps 关注规划循环、工具调用、多 Agent 协作，MLOps 关注模型训练与部署。
[⭐⭐⭐] [AgentOps]

AI Agent 三大能力
感知（Perception）、决策（Cognition）、行动（Action）。
[⭐⭐⭐] [AI 概念]

Agent 四大组件
LLM、Memory、Tools、Planning。
[⭐⭐⭐] [AI 概念]

Agent 短期记忆 (Short-term Memory)
当前会话的上下文窗口。
[⭐⭐⭐] [AI Agent]

Agent 长期记忆 (Long-term Memory)
跨会话持久化的记忆：向量数据库、知识图谱。
[⭐⭐⭐] [AI Agent]

Agent 工具调用 (Tool Use)
Agent 调用外部 API、函数、数据库的能力。
[⭐⭐⭐] [AI Agent]

Agent 规划 (Planning)
Agent 分解复杂任务为子任务的能力。
[⭐⭐⭐] [AI Agent]

Agent 反思 (Reflection)
Agent 对自身输出进行评估与修正的能力。
[⭐⭐⭐] [AI Agent]

Agent 工具设计原则
原子性、可组合、可发现、有错误处理、有超时控制。
[⭐⭐⭐] [AgentOps]

Agent Function Calling
LLM 以结构化方式调用预定义函数。
[⭐⭐⭐] [OpenAI 2023]

Agent ReAct 循环
Reason → Act → Observe → Reason 循环。
[⭐⭐⭐] [Princeton]

Agent Plan-and-Execute
先规划完整计划、再逐步执行。
[⭐⭐⭐] [AI Agent]

Multi-Agent 协作模式
Supervisor（监督者）、Peer（对等）、Hierarchical（层级）、Network（网络）。
[⭐⭐⭐] [Multi-Agent]

AutoGen 多 Agent 框架
Microsoft 2023：基于对话的多 Agent 协作。
[⭐⭐⭐] [Microsoft Research]

CrewAI
基于角色与任务的多 Agent 框架。
[⭐⭐⭐] [CrewAI]

LangGraph Multi-Agent
基于状态图的多 Agent 编排。
[⭐⭐⭐] [LangChain 2024]

Agent-to-Agent (A2A) Protocol
Google 2025 提出的 Agent 间通信标准协议。
[⭐⭐⭐] [Google A2A]

A2A 核心特性
Agent Card、能力发现、任务委派、安全认证、流式响应。
[⭐⭐⭐] [Google A2A]

Model Context Protocol (MCP)
Anthropic 2024 提出的模型上下文协议。
[⭐⭐⭐] [Anthropic MCP]

MCP vs A2A
MCP 关注 LLM 与工具的连接，A2A 关注 Agent 与 Agent 的协作。
[⭐⭐⭐] [业界实践]

MCP 三大原语
Resources、Prompts、Tools。
[⭐⭐⭐] [Anthropic MCP]

AgentBench / ToolBench
Agent 性能评估基准。
[⭐⭐⭐] [学术界]

SWE-bench
软件工程任务上的 LLM 基准。
[⭐⭐⭐] [Princeton 2024]

GAIA
通用 AI 助手基准测试。
[⭐⭐⭐] [Meta/HuggingFace 2023]

Agent 失败模式
循环卡死、错误传播、工具滥用、安全越狱、成本失控、上下文泄漏。
[⭐⭐⭐] [AgentOps]

Agent 安全 (Agent Safety)
防止 Agent 执行危险操作：权限沙箱、用户确认、操作审计。
[⭐⭐⭐] [AgentOps]

Agent 限流 (Agent Rate Limiting)
防止 Agent 无限调用 API 造成成本失控。
[⭐⭐⭐] [AgentOps]

Agent 评估 (Agent Evaluation)
对 Agent 完成任务的成功率、效率、成本、安全的综合评估。
[⭐⭐⭐] [AgentOps]

Agent Observability (Agent 可观测性)
LangSmith、Langfuse、Helicone、Arize Phoenix。
[⭐⭐⭐] [AgentOps]

C5 · TOGAF 10 ADM 阶段

TOGAF (The Open Group Architecture Framework)
The Open Group 维护的企业架构框架，最新版本 10（2024）。
[⭐⭐⭐⭐] [The Open Group]

TOGAF 10 (2024)
TOGAF 第 10 版，2024 年发布，强调敏捷、可持续、AI。
[⭐⭐⭐⭐] [The Open Group]

ADM (Architecture Development Method)
TOGAF 的核心方法论，10 个迭代阶段。
[⭐⭐⭐⭐] [The Open Group]

预备阶段 (Preliminary Phase)
建立架构能力框架、原则、治理。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 A：架构愿景 (Architecture Vision)
定义架构工作范围、利益相关方、愿景。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 B：业务架构 (Business Architecture)
开发业务能力、流程、组织、功能的架构。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 C：信息系统架构 (Information Systems Architectures)
包括数据架构与应用架构两个子阶段。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 C1：数据架构 (Data Architecture)
定义企业数据资产、结构和治理。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 C2：应用架构 (Application Architecture)
定义应用系统蓝图与交互。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 D：技术架构 (Technology Architecture)
定义基础设施、中间件、网络的架构。
[⭐⭐⭐⭐] [TOGAF ADM]

阶段 E：机会与解决方案 (Opportunities & Solutions)
识别实施项目、估算工作量、排序。
[⭐⭐⭐] [TOGAF ADM]

阶段 F：迁移规划 (Migration Planning)
制定详细的迁移路线图。
[⭐⭐⭐] [TOGAF ADM]

阶段 G：实施治理 (Implementation Governance)
治理实施过程确保符合架构。
[⭐⭐⭐] [TOGAF ADM]

阶段 H：架构变更管理 (Architecture Change Management)
持续监控变更并启动新 ADM 周期。
[⭐⭐⭐] [TOGAF ADM]

ADM 需求管理 (Requirements Management)
贯穿 ADM 全过程的横切阶段。
[⭐⭐⭐] [TOGAF ADM]

架构治理 (Architecture Governance)
对架构工作的治理框架、流程、合规。
[⭐⭐⭐⭐] [TOGAF]

架构原则 (Architecture Principles)
指导架构决策的高层准则。
[⭐⭐⭐] [TOGAF]

架构仓库 (Architecture Repository)
存储架构工件、参考模型、标准。
[⭐⭐⭐] [TOGAF]

架构视图 (Architecture Views)
为不同利益相关方呈现的不同视角。
[⭐⭐⭐] [TOGAF]

架构工件 (Architecture Artifacts)
目录、矩阵、图：能力目录、应用矩阵、技术图。
[⭐⭐⭐] [TOGAF]
