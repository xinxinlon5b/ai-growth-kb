SOP · 🏗️ FDE 入企交付方向（做深做重）

方向标签：下场把项目做扎实
v2 更新：2026-09-10 — 整合 38 号「FDE 全流程可指导方法论 v1」8 阶段 8 SOP 框架
v1 链接：5 步版本保留在末尾供对比

一、为什么这条路径

当接单进入交付阶段，真正的价值在「脏活」——知识库项目七成是帮客户梳理乱文档。FDE 只有 3-5 年红利期，现在练正是窗口。

8 阶段全流程方法论（基于 Hermes 队长 + FDE 教程 6 阶段 + B 站 8 阶段教程 MECE 揉合）：

[阶段 0] 立项选赛道          ← PSF 三关：痛点 / 经济性 / 可行性
    ↓
[阶段 1] 定义结果与责任边界  ← 结果定义书（合同附件级）
    ↓
[阶段 2] 调研现场与设计架构  ← 五份地图 + MVD 三军规
    ↓
[阶段 3] POC + 质量评估      ← 评测体系（准确率/忠实度/召回率）
    ↓
[阶段 4] 企业集成 + 受控试用  ← 热修复文化 + 变革管理
    ↓
[阶段 5] 全面上线 + 采用 + 交接  ← 灰度 5% → 监控 → 回滚 → 培训
    ↓
[阶段 6] 守约 + 增量扩展     ← 客户健康分 + QBR
    ↓
[阶段 7] 复盘沉淀 + 迁移复用  ← 灯塔筛选 + 经验资产化

二、适合谁

适合已有 1-2 个真实项目正在交付/即将交付的人；目标 = 按 FDE 标准跑完一个项目并复盘。

三、执行 SOP（8 阶段 × 8 SOP）

阶段 0：立项选赛道 — SOP 1「PSF 三关」

解决什么：95% 的企业 AI 项目死在「做错的问题」上，不是技术差。

三关：
1. 痛点检验：必须翻译到"具体的人 + 具体的事"（如"客服主管每周一花 3 小时从 4 个系统手动汇总上周升级工单"）
2. 经济性检验：能落在"CEO 关注的 5 个问题之一"吗？
3. 可行性检验：数据在哪 + 准确率门槛多少？两个数字问出来，能筛掉一半客户

产出物：《PSF 判断书》3 行字——「做的什么问题 / 量化价值估算 / Go-改-No」

阶段 1：定义结果与责任边界

写清：给谁用 / 改善什么 / 谁负责 / 成功标准（可量化）/ 上线条件
产出物：合同附件级「结果定义书」

阶段 2：调研现场与设计架构 — SOP 3「五份地图」+ SOP 2「MVD 三军规」

解决什么：进场后踩坑绝大多数是因为「不知道客户那边发生了什么」

五份地图（1-2 周尽调）：
1. 数据地图——重点标"哪个被信任"（不是有什么）
2. 流程地图——影子工作法（跟一个真实用户过一天）
3. 组织地图——找"知识枢纽"（职位不高但所有人找他的人）
4. 系统地图——技术环境 + 变更管理流程（很多项目时间表在第一天就注定破产）
5. 政治地图——动了谁的奶酪、被自动化的流程是不是某部门权力来源

MVD（最小可行部署）三军规：
1. 真实数据没有例外——客户必须带真实业务数据
2. 缩小范围不缩价值——不砍方案深度，只砍覆盖面
3. 定死截止时间——以周计不是以月计（Palantir 训练营 1-5 天，Sierra 最快 4 周）

阶段 3：POC + 质量评估 — SOP 4「评测体系」

AI 产品命门——没有评测就没有优化方向

三步：
1. 评估方案 + 黄金集（50-100 条起步，必须来自客户真实业务素材）
2. 评估执行（客观题自动化，主观题维度化）
3. 评估反馈 + 闭环（生产环境持续采样）

三维度指标：
- 准确率——答案对不对
- 忠实度——是否按参考文档答（避免 AI 凭常识胡诌）
- 召回率——检索阶段找回了多少

上线底线：通过率 ≥ 50% + 提效率 > 0（数学推导临界值）

ROI 计算：提效率 × 频次 × 人工耗时 = 节省金额（如一年省 290 万）

阶段 4：企业集成 + 受控试用 — SOP 5「热修复文化」+ SOP 6「变革管理」

热修复文化（以天/小时计迭代）：
- 反馈必须直达写代码的人
- 迭代优先级按"使用阻塞度"排，不是"功能重要度"
- 每天收工问一个问题：今天的改动让用户明天的哪一刻更顺了？

变革管理三件套：
- 支持者经营——给讲得出去的故事 + 给战功 + 给安全感
- 影响者经营——资深分析师/老师傅/部门里"问他就行"的人
- 受损者安抚——提前设计"受损者的出路"（公开承诺不裁员 + 守门人转教练）

阶段 5：全面上线 + 采用 + 交接

  • 灰度 5% → 监控 → 回滚预案
  • 客户培训 / 内部讲师培养
  • 产出：上线 + 监控 + 回滚 + 培训手册

阶段 6：守约 + 增量扩展

  • 客户健康分（使用 / 价值 / 关系 / 商业四类信号）
  • 季度业务回顾 QBR（讲客户语言、不讲产品语言）
  • 产出：QBR + 健康分看板

阶段 7：复盘沉淀 + 迁移复用 — SOP 7「灯塔筛选」+ SOP 8「经验资产化」

灯塔筛选（客户优先级矩阵）：
- 两维度：灯塔价值 × 学习价值
- 警惕三类高危客户：需求蝗虫 / 无主之地 / 宇宙级需求
- 红线：单份合同 10 万美元以上 FDE 才算得过账

经验资产化（从 1 到 N）：
- 部署模板化（IaC）
- 集成组件库化
- 检查清单文化
- 自动化汇报
- 现场反哺产品（每次实施首先是构建与学习的机会）

四、避坑（重要）

  • 跳过 PSF 第三关就开工——半年后发现数据不够用
  • 用"脱敏样例数据"做验证——概念验证坟墓
  • 把"客户说要 AI"当需求——警惕翻译过的痛点
  • 把 MVD 理解成"阉割版大方案"——功能砍 7 成做得四不像
  • 客户不让碰真实数据 = 高危信号
  • 跳政治地图——上线演示那天被角落里的另一部门主管反噬
  • 评测集用 demo 数据——上线就翻车
  • 反馈层层转述——用户心凉了
  • 接错灯塔还觉得在做事——产品被带歪

见客户时的引用话术

"我们的 FDE 流程是 8 阶段全流程——
立项（PSF 三关）→ 定义结果 → 调研设计（五份地图 + MVD）→ POC 评测 → 企业集成（热修复 + 变革管理）→ 上线交接 → 守约增量 → 复盘沉淀。

这套做法参照：
- Palantir 官方文档（FDE 发明者）
- OpenAI Deployment Company（2025 年独立成公司）
- Anthropic Applied AI 团队 JD（agentic systems + MCP + skills）
- MIT/BCG 失败率研究（为什么需要 FDE）
- ISO 42001（AI 治理国际标准）
- DORA 四指标（交付能力度量）

不是某家厂商的偏好，是国际/行业/原厂共识。"
