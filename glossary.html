07 · 专业大词典（术语速查）

学习路径中反复出现但容易混淆 / 新人才接触的术语，按字母序排列。
词条解释 = 该术语在企业 AI / FDE / 自媒体语境下的常见用法 + 1-2 句出处。

A

Agent / 智能体

能自主感知环境、做决策、执行动作的 AI 程序。在企业落地里，常见形态是「接业务系统 API + 调用工具 + 沉淀记忆」。

来自旭东AI：FDE 把业务问题翻译成 AI 能执行的规则，靠 Agent 落地到员工天天用的场景。

AI 焦虑

老板「听说 AI 很厉害但不知道能干嘛」的心理状态。是 FDE 接单的真实切入点——别上来推大方案，先缓解焦虑再上系统。

来自皮皮：客户一个月 8 万出三个月，看你能不能解决 AI 焦虑。

API（应用程序接口）

让两个软件互相调用对方能力的标准。在 FDE 项目里，第一步永远是问"数据有没有 API"，没 API 就只能靠人肉复制，等于玩具。

来自清华鑫哥：数据靠人肉复制喂 AI=玩具。

AI 转型（AI Transformation）

企业用 AI 重构业务流程、组织架构、数据资产的过程。注意：不是装几个 Agent，是"组织升级"。

来自曾鸣：未来组织就做两件事——运营自动化 + 战略决策高质量化。

B

Benchmark（基准对比）

把客户现有的"人工作业流程"和"AI 工作流"放一起比较，算产出率提升的幅度。是报价的依据。

来自 zionisreal：选 5 个业务流做 Benchmark，算一年省多少。

半监督 / 微调（Fine-tuning）

用客户自己的数据训练模型，让模型更懂行业话术。常见于知识库项目，但只有数据够多才有意义。

来自视频库「AI编程工具链」分类，多条提到。

C

ChatGPT / Claude / Kimi / DeepSeek

常见大语言模型。ChatGPT 综合强、Claude 长上下文与代码能力强、Kimi 长文本处理强、DeepSeek 性价比高。

见「AI 编程工具链」类 34 簇。

CPS（Cost Per Sale / 销售分成）

按成交结果分成的收费模式。AI 项目里常用于"按帮客户省的钱分几成"。

来自皮皮：帮他省了多少钱分几成。

D

Demo（最小可用原型）

MVP 的更轻量版本。客户不在意你的代码好不好看，只看 Demo 跑得通跑不通。

来自旭东AI：先切一个最痛的小环节做 Demo。

端到端（End-to-End）

从用户输入到最终业务结果全程打通的状态。FDE 项目的目标不是做 Demo，而是做"端到端的业务流程自动化"。

来自旭东AI / 清华鑫哥多处。

DXY（滴鑫盈？待确认）

见原视频库，暂未明确中文释义。建议回查原视频。

E

ERP（企业资源计划）

管理企业核心业务（订单、库存、采购、财务）的系统。是 FDE 找数据的第一站——ERP 里通常有最干净的订单/客户数据。

来自旭东AI：ERP 里面的一些订单。

ELO / Expert Loop / 专家回路

企业把"老法师经验"显性化、AI 化的过程。是企业 AI 落地里最值钱但最难做的事。

来自清华鑫哥："把人的经验说清楚"。

F

FDE（Forward Deployed Engineer / 前线部署工程师）

驻场到客户企业、负责把 AI 方案真正落地的工程师。不是远程写代码外包，而是"和销售一起跑客户、和老板一起开会"。

来自小智：把客户的"工业时代组织"改造成"AI时代组织"。

FDE 轻量落地流程

5 步：① 业务诊断 → ② Demo 验证 → ③ 落地实施 → ④ 运行优化 → ⑤ 培训迭代。

来自旭东AI 第 27 集。

FDE 红利期

行业普遍认为 FDE 在中国只有 3-5 年的窗口期（2025-2030）。过了之后要么规模化、要么被标准化产品取代。

来自 learning_paths p3。

G

刚性自动化

涉及真金白银 / 安全风险的环节，先把专家经验写成"固定代码规则"（if 湿度 < 阈值 then 浇水），AI 只做交互层。

来自智慧农业落地：AI 只做降门槛，核心执行用确定性规则。

GPTs / GPT Store

OpenAI 的"应用商店"，可以发布定制 GPT。在中国对应"扣子 / Coze"。

见「AI 编程工具链」相关簇。

H

Hermes（神使 / 智能体框架）

见 OpenClaw / Hermes 相关 23 簇。

I

Insight（洞察）

从视频转写里抽出的结构化要点。原网站给你打了 337 条 insight，是知识库的精华。

来自 growth-panel-online 数据结构。

IT 部门

FDE 项目的常见阻力来源——IT 牵头 AI 项目容易被业务部门卡（数据共享、权限）。需要老板拍板才能打通。

来自董俊豪：IT 牵头做 AI，销售总监不愿意交数据。

K

KPI（关键绩效指标）

AI 项目要量化效果时必谈。常见 KPI：响应时长缩短 X%、人力节省 X 人月、订单转化率提升 X%。

见 zionisreal 报价方法论。

扣子（Coze）

字节出品的 Agent 搭建平台。国内最常用的"无代码搭 Agent"工具之一。

见视频库「智能体」分类。

L

LLM（大语言模型 / Large Language Model）

如 GPT-4 / Claude / Kimi / DeepSeek 等。是所有 Agent、知识库、文案工具的底座。

通用概念。

落地最优单元

企业 AI 落地时最适合作为第一个项目的"最小业务切片"——通常选"重复 + 有数据 + 可校验"的工作。

来自董俊豪 / DD讲AI。

M

MVP（Minimum Viable Product / 最小可用产品）

比 Demo 更进一步，可以接真实业务数据的产品形态。是"试点→规模化"的中间形态。

来自旭东AI 27 集。

MCP（Model Context Protocol）

让 AI 模型调用外部工具（API / 数据库 / 文件）的协议标准。是 2025 年最重要的 Agent 互通协议之一。

见视频库「智能体」分类。

MC 公司

MCN / Multi-Channel Network 的缩写，在小智的案例里指一家 8000 人规模的代运营/内容公司。

来自小智案例。

盲签合同

没有经过诊断就签合同的接单方式——FDE 项目里的大忌，因为需求不清就交付必烂尾。

来自清华鑫哥多处。

N

NLP（自然语言处理）

让机器理解人类语言的技术。LLM 时代 NLP 能力已被 LLM 主导，但垂直场景（如合同审查、客服分流）仍需定制。

通用概念。

1 号位

企业里"最终拍板的那个人"——通常是创始人或 CEO。FDE 项目里必须搞定 1 号位，否则跨部门推不动。

来自旭东AI：跟创始人（1 号位）挖痛点。

O

OPC（One Person Company / 一人公司）

个人独立创业者。AI 时代 OPC 越来越多，靠 AI 杠杆做原本需要团队才能做的事。

来自皮皮：现在很多 OPC 都是产品技术运营出身。

OpenClaw

你常用的一个 AI Agent 平台（详见你视频库的「智能体·OpenClaw·Hermes」分类，23 簇）。

OMO（Online-Merge-Offline）

线上线下融合。在 AI 落地场景里，指"AI 把线上数据和线下流程打通"。

来自多个商业案例。

P

Prompt（提示词）

你给 AI 的指令。在 FDE 项目里，"把业务问题翻译成 AI 能执行的规则"= 把业务流程写成 Prompt / 工作流配置。

通用概念。

PMF（Product-Market Fit / 产品市场匹配）

产品真的被市场需要的那个临界点。FDE 项目做完 MVP 后要尽快验证 PMF。

通用概念。

Q

4 阶段落地法

AI 转型分四阶段走：① 导入期（建认知）→ ② 典范期（试点）→ ③ 扩展期（复制）→ ④ 生化期（建 AI 文化 + 数据平台）。

来自旭东AI 第 15 集。

Q1 / Q2 / Q3 / Q4

季度。原视频里多用来讨论"上半年做什么、下半年做什么"的节奏。

R

ROI（投资回报率）

FDE 项目报价的核心论证——"花 20 万换 100 万效率提升，ROI = 5x"。

来自 zionisreal。

RPA（机器人流程自动化）

让软件机器人模拟人操作电脑的传统自动化工具。AI 时代的 RPA 升级为"AI Agent + RPA"，AI 做判断，RPA 做执行。

见视频库「效率工具」分类。

S

Skill（技能包）

OpenClaw / Coze 等平台里"打包好的可复用工作流"。你工作台里"按岗位设计"就是把工作流固化成 Skill。

来自刘小排 / 你工作台的方法论。

SOP（标准操作流程）

把一项工作拆成可重复执行的步骤。本知识库的核心产物之一。

通用概念。

SaaS（Software as a Service）

按订阅付费的软件。AI 项目里很多服务商在做"AI SaaS"，但 FDE 的"项目制 + 结果分成"模式更主流。

通用概念。

T

Token（模型计费单位）

大模型按 Token 计费。1 个汉字 ≈ 1.5-2 个 Token。Token 成本是 Agent 自用的核心成本。

来自龙虾系列。

投产比（ROI 别名）

见 ROI 词条。

V

Vibe Coding

"凭感觉写代码"，让 AI 主导大部分编码工作、你只做关键判断。是 Cursor / Claude Code 时代的标志性工作方式。

见「AI 编程工具链」分类。

VLM（视觉语言模型）

能"看图说话"的多模态模型，如 GPT-4V / Qwen-VL / Claude 3.5 Sonnet。常用在截图分析、文档识别。

见视频库多个相关视频。

W

Workflow / 工作流

把多个步骤串起来的自动化流程。Coze / Dify / n8n 是常见的可视化工作流平台。

通用概念。

X

信息化 → 数字化 → AI 化

企业进化的三阶段：
- 信息化：用软件管流程（ERP / OA / CRM）
- 数字化：数据可采集、可分析
- AI 化：用模型自动决策 / 执行

来自旭东14：没数字化就没 AI 化。

Y

Y Combinator（YC）

全球最知名的创业加速器。在 AI 时代是 FDE / AI 应用创业的重要风向标。

见视频库「AI 认知」分类相关访谈。

验收 / 交付

项目做完的标准——不是"代码 push 完"，而是"客户业务跑通 + 培训完成 + 文档沉淀"。

来自清华鑫哥多处。

Z

知识库（Knowledge Base）

把企业里"散落在员工脑子里的经验 + 文档 + 历史数据"沉淀成可被 AI 检索的结构化资产。FDE 项目里 7 成工作量在知识库。

来自清华鑫哥 / 王总/实操。

智能体

见 Agent。

自媒体获客

靠内容（短视频 / 公众号 / 知乎）吸引潜在客户主动找上门。FDE 时代"一个视频=24小时销售"。

来自清华鑫哥。

组织升级

把"工业时代的科层制组织"改成"AI 时代的扁平化 + 自动化组织"。这是 FDE 服务的真正卖点，不是装 Agent。

来自小智 / 曾鸣。

数字 / 符号

1 号位

见 N 类。

4 阶段落地法

见 Q 类。

4 象限筛需求法

把需求分成「战略 / 策略 / 底线 / 优化」四类，优先做"策略"类（影响增长），忍住不做"优化"类（体感强但没用）。

来自光羽。

5 步报价法

① 选 5 个业务流 → ② 做 SOP Benchmark → ③ 算省钱数字 → ④ 按价值报 → ⑤ 结果导向合同。

来自 zionisreal。

10x 杠杆

AI 让你"一个人干原来 10 个人的活"的杠杆效应。是 OPC 时代的核心叙事。

见多个访谈类视频。

词条总数：50+ 实战词 + 30+ 权威词。
维护原则：每次你学到新术语，加一行；每次和老 FDE 沟通时遇到听不懂的词，补一行。

权威术语篇（来自 A-D 12 个权威来源）

这一部分来自 08-权威支撑/ 里的 12 个一手 / 经典来源。
见客户 / 写技术方案 / 参加行业会议时，这些词会高频出现。

H

Harness（执行容器）

包裹 Agent 的运行时，负责工具调用、状态管理、动作边界、错误隔离。
Anthropic 生产级 Agent 体系的核心抽象。

见 A2-Anthropic生产级Agent白皮书。

Human-in-the-Loop（人在回路）

高危动作必须人工确认的机制。不是"AI 自动 + 人工看"，是"AI 提交 + 人工裁决"。

见 A2 / D1 / D3。

Human Handoff（人机交接）

Agent 把上下文打包好交给人工执行。交接信息要完整，不能"传一半"。

见 D1 Google 框架。

G

Guardrail / 护栏

AI 绝对不能做什么的硬约束。和 Prompt（应该做什么）相反。
护栏不是文档，是真实失败的反向工程。

见 A1 / A2 / B2 / D1 / D3。

Function Calling / 函数调用

LLM 调外部工具的标准方式。OpenAI 2023 年提出，现在全行业通用。

见 D3。

A

Agentic Workflow（智能体工作流）

多步骤、多工具、有状态的工作流，由 Agent 主导执行。

见 B2。

Action Boundary / 动作边界

Agent 能做什么的硬约束。用代码限制，不是用 Prompt 建议。

见 A2。

Action Tiering / 动作风险分级

按风险把动作分成 L0-L4（Anthropic）或 Low-Critical（Google）或只读/写本/写外（OpenAI），分级处理。
三家厂商收敛到同一思想。

见 A2 / D1 / D3。

Action Allowlist / 动作白名单

Agent 在创建时定义"允许调用的工具列表"，不在列表里的工具一律拒绝。

见 D1。

Audit Trail / 审计日志

每个 AI 调用都留痕：谁、什么时候、输入、输出、模型、工具、护栏、结果。

见 B4 / D2。

Actionability（可操作性）

方案能被实际执行的程度。FDE 给客户的不是 PPT，是"今天就能做"的步骤。

通用概念。

F

Failure Injection / 故障注入

主动制造异常（错误数据 / 工具失败 / 网络延迟）验证系统是否死。

见 A3 + C2。

Function（函数 / 工具）

Agent 可调用的具体能力。OpenAI 的标准叫 Function Calling。

见 D3。

R

RAG（检索增强生成）

"先检索相关文档，再让 LLM 看文档回答"的架构。企业私有知识问答的标准方案。

见 B3。

Recall@K（Top-K 召回率）

前 K 个检索结果里包含正确答案的比例。RAG 核心指标，建议 > 80%。

见 B3。

MRR（平均倒数排名）

正确答案排名的倒数。RAG 另一个核心指标，建议 > 0.7。

见 B3。

Faithfulness（忠实度）

答案不偏离原文的程度。RAG 防幻觉的核心指标，建议 > 90%。

见 B3。

Rerank（重排序）

用更精确的模型（如 Cross-Encoder）二次排序召回结果，比单纯向量检索更准。

见 B3。

Risk-Driven Architecture（风险驱动架构）

架构决策由"风险"驱动，不是由"听起来高级"驱动。没风险就不加组件。

见 C1。

Rollback（回滚）

业务回滚 ≠ 模型回滚。业务回滚是撤销 Agent 已经造成的业务影响（取消订单、退款、撤回邮件）。

见 A2 / B2。

RBAC（基于角色的权限控制）

按角色分配权限。Agent 知道"我是谁"，自动应用权限。

见 B4。

E

Embedding（向量化）

把文本转成数字向量，让语义相似度可以计算。是 RAG 的基础。

见 B3。

C

Chunking（文档切分）

把长文档切成适合检索的小段。保留语义边界 + 加 overlap + 加 metadata。
RAG 项目 80% 的脏活在 chunking。

见 B3。

Chaos Engineering（混沌工程）

主动制造异常验证可靠性的方法论。Netflix 提出。
不是为了证明系统多强，是为了证明异常下不死。

见 C2。

Chaos Monkey（混沌猴）

Netflix 工具，随机 kill 服务实例，验证系统弹性。

见 C2。

Canary Deployment（金丝雀发布）

小流量（5%）试新版本 → 没问题 → 25% → 50% → 100%。出问题 1 秒回滚。

见 B1 / D2。

Compensating Transaction（补偿事务）

业务回滚的具体操作：发出去的邮件撤回、创建的订单取消、转账退款。

见 B2。

Content Safety（内容安全）

防止违规 / 误导 / 泄露内容。包括输入过滤、输出过滤、黑名单词表。

见 B4。

Compliance（合规）

符合行业法规要求。不同行业不同：金融/医疗/教育/跨境/政府。

见 B4 / D2。

M

Model Gateway（模型网关）

包裹 LLM 调用的中间层，负责路由 / 限流 / 鉴权 / 缓存 / 降级 / 日志。

见 B1 / D2。

Middle Layer（中间层）

同 Model Gateway，但更强调"在业务和模型之间"的位置。

Moderation API

OpenAI 的内容审核 API，自动检测违规内容。

见 D3。

Multi-Agent（多 Agent）

多个 Agent 互相调用 / 协作 / 流水线。适合复杂业务，但工程复杂度高。

见 B2。

MCP（Model Context Protocol）

让 AI 模型调用外部工具的协议标准。Anthropic 推动，2025 年成为行业事实标准。

见 08-权威支撑/ 及各卡。

T

Trace / 链路追踪

单个请求从入口到出口的完整调用链。生产环境必备。

见 B1 / D2。

Token（模型计费单位）

大模型按 Token 计费。1 个汉字 ≈ 1.5-2 个 Token。

已在实战词里。

D

DDD（领域驱动设计）

Eric Evans 2003 年的建模方法论。FDE 进客户画业务地图的祖宗。

见 C3。

Domain Service（领域服务）

跨实体的业务逻辑（如转账、订单取消），单独封装。

见 C3。

Data Isolation（数据隔离）

不同客户/业务的数据分开处理。绝对不能让数据串台。

见 B4。

Data Desensitization（数据脱敏）

喂给模型前去掉敏感字段（身份证 / 银行卡 / 商业机密）。

见 B4。

DXY（滴鑫盈？待确认）

见原视频库，暂未明确中文释义。

B

Boundary Verification（边界验证）

明确 Agent 能做什么 / 不能做什么 / 不确定什么，并用边界 case 测试。

见 A3。

Bounded Context（限界上下文）

每个部门有自己的数据模型，互不污染。DDD 核心概念。

见 C3。

Bedrock（AWS LLM 托管服务）

AWS 的多模型统一接入平台。

见 D2。

V

VDNA（业务本体图谱）

FDE 圈对 DDD 的可视化延伸——进客户画"业务地图"。

见 C3。

Verifiable Criteria（可验证标准）

可量化的评估指标。不是"体验更好"，是"响应时长从 30s 降到 5s"。

见 A3。

Value Object（值对象）

无 ID 的属性集合。DDD 概念。地址、金额、日期等。

见 C3。

E

Entity（实体）

有 ID 的领域对象，状态可变。订单、客户、合同。DDD 概念。

见 C3。

S

Step Limit（步数限制）

美国安全合规标准，AI 服务商常引用。

见 D2。

Saga Pattern（Saga 模式）

长事务的业务回滚方案。多步操作中失败能优雅撤销。

见 B2。

P

Prompt Injection（提示词注入）

用户用恶意 prompt 让模型做不该做的事。安全威胁之一。

见 B4。

POC（Proof of Concept / 概念验证）

证明"AI 能做这件事"。和"Production（生产投产）"是两回事。

见 A1。

Production（生产投产）

证明"AI 在真实业务里稳跑"。POC 通过不等于 Production 就绪。

见 A1。

PrivateLink（AWS 私有连接）

AWS 内网专线，AI 调用不走公网。数据安全标配。

见 D2。

O

Orchestration（编排）

多个 Agent/工具如何协作。编排方式决定系统复杂度。

见 B2。

Observability（可观测）

看清系统内部状态。包含 Trace + Metrics + Logs + Alerts。

见 B1 / D2。

K

KMS（AWS 密钥管理）

客户自管加密密钥。AWS 数据安全核心组件。

见 D2。

L

Loop Control（循环控制）

防 Agent 死循环：最大步数 / 最大时间 / 最大 Token / 重复检测 / 用户中断。

见 D3。

I

In-Context Learning（上下文学习）

LLM 通过 Prompt 里的例子学习任务的能力。RAG 是它的工程化。

通用概念。

A

Agent + RAG

不是 RAG 替代 Agent，是 Agent 把 RAG 当成一个工具。
Agent 决定"要不要查 / 查几次 / 查什么"。

见 D3。

Aggregate Root（聚合根）

聚合的入口实体。要改子实体必须通过聚合根。

见 C3。

Aggregate（聚合）

一组相关实体的根。订单 = 聚合根 + 订单项 + 地址 + 支付。

见 C3。
