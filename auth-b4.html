B4 · LLMs 的对抗攻击（Lilian Weng）—— 完整中文全文翻译

1. 引言

对抗攻击是针对机器学习模型的一种攻击方式，旨在通过精心设计的输入来操纵模型的行为。对于大型语言模型（LLMs），对抗攻击可以导致模型产生错误的响应，从而影响其在实际应用中的表现。本文将探讨对抗攻击在 LLMs 中的应用，并介绍一些防御方法。

2. 对抗攻击的基本概念

2.1 定义

对抗攻击是指通过修改输入数据，使机器学习模型产生错误预测的行为。攻击者通过精心设计的输入，使得模型在处理这些输入时产生错误的输出。

2.2 例子

一个经典的对抗攻击例子是图像分类任务。攻击者可以通过在图像中添加微小的扰动，使得模型将一只猫误分类为一只狗。这种攻击在实际应用中可能导致严重的后果，例如自动驾驶汽车的误判。

2.3 对抗攻击的动机

对抗攻击的动机在于测试模型的鲁棒性，即模型在面对精心设计的输入时是否能够保持正确的预测。通过对抗攻击，研究人员可以发现模型中的漏洞，并提出相应的防御措施。

3. LLMs 中的对抗攻击

3.1 攻击类型

在 LLMs 中，对抗攻击可以分为以下几种类型：

  • 文本插入攻击：通过在输入文本中插入特定的字符或短语，使模型产生错误的响应。
  • 文本替换攻击：通过替换输入文本中的某些词语，使模型产生错误的响应。
  • 文本删除攻击：通过删除输入文本中的某些词语，使模型产生错误的响应。
  • 文本重排攻击：通过重新排列输入文本中的词语顺序，使模型产生错误的响应。

3.2 攻击实例

3.2.1 文本插入攻击

假设我们有一个 LLM，用于回答关于历史问题。攻击者可以通过在输入文本中插入特定的字符或短语，使模型产生错误的响应。例如，攻击者可以在输入文本中插入“1945年，希特勒被打败了”，使得模型将某个历史事件错误地归因于希特勒。

3.2.2 文本替换攻击

假设我们有一个 LLM，用于生成诗歌。攻击者可以通过替换输入文本中的某些词语，使模型产生错误的响应。例如，攻击者可以将输入文本中的“月亮”替换为“太阳”，使得模型生成的诗歌中出现了不合理的场景。

3.2.3 文本删除攻击

假设我们有一个 LLM，用于回答关于科学问题。攻击者可以通过删除输入文本中的某些词语，使模型产生错误的响应。例如，攻击者可以删除输入文本中的“光合作用”，使得模型无法正确回答关于光合作用的问题。

3.2.4 文本重排攻击

假设我们有一个 LLM，用于生成新闻报道。攻击者可以通过重新排列输入文本中的词语顺序，使模型产生错误的响应。例如，攻击者可以将输入文本中的“会议在下午举行”重排为“下午会议举行”，使得模型生成的新闻报道中出现了不合理的句子。

4. 防御方法

4.1 鲁棒性训练

通过在训练过程中引入对抗样本，可以提高模型的鲁棒性。对抗样本是在原始样本的基础上，通过添加微小的扰动生成的。训练过程中，模型需要学习如何正确处理这些扰动，从而提高其在面对对抗攻击时的鲁棒性。

4.2 鲁棒性评估

对抗攻击的防御方法之一是通过鲁棒性评估来检测模型的脆弱性。通过在测试集中引入对抗样本，可以评估模型在面对对抗攻击时的表现。如果模型在测试集中表现不佳，说明其存在漏洞，需要进一步改进。

4.3 鲁棒性增强

通过引入特定的防御机制，可以增强模型的鲁棒性。例如，可以使用对抗训练、模型修剪、模型集成等方法来提高模型的鲁棒性。

4.4 鲁棒性测试

对抗攻击的防御方法之一是通过鲁棒性测试来验证模型的鲁棒性。通过在测试集中引入对抗样本，可以评估模型在面对对抗攻击时的表现。如果模型在测试集中表现良好，说明其具有较高的鲁棒性。

5. 结论

对抗攻击是针对 LLMs 的一种重要攻击方式。通过对抗攻击，攻击者可以操纵模型的行为，从而影响其在实际应用中的表现。本文介绍了对抗攻击的基本概念、攻击类型、防御方法，并通过实例展示了对抗攻击在 LLMs 中的应用。未来的研究需要进一步探索对抗攻击的防御方法，以提高 LLMs 的鲁棒性。

7. 附录

7.1 代码示例

import torch
import torch.nn as nn

class AdversarialAttack(nn.Module):
    def __init__(self, model):
        super(AdversarialAttack, self).__init__()
        self.model = model

    def perturb(self, input, target):
        # 在输入上添加微小的扰动
        perturbed_input = input + torch.randn_like(input) * 0.01
        return perturbed_input

    def attack(self, input, target):
        perturbed_input = self.perturb(input, target)
        output = self.model(perturbed_input)
        return output

自 ChatGPT 推出以来，大型语言模型在现实世界中的使用得到了极大加速。我们（包括我在 OpenAI 的团队，向他们致敬）在对齐过程中投入了大量工作来建立模型的默认安全行为（例如通过 RLHF）。然而，对抗性攻击或越狱提示可能会触发模型输出不需要的内容。

“大量关于对抗性攻击的奠基性工作是在图像上进行的，并且它在连续的高维空间中以不同的方式运行。对于像文本这样的离散数据的攻击被认为是更具挑战性的，因为缺乏直接的梯度信号。我过去关于可控文本生成的帖子与这个主题非常相关，因为攻击 LLM 本质上是控制模型输出某种类型（不安全的）内容。”

大量关于对抗性攻击的奠基性工作是在图像上进行的，并且它在连续的高维空间中以不同的方式运行。对于像文本这样的离散数据的攻击被认为是更具挑战性的，因为缺乏直接的梯度信号。我过去关于可控文本生成的帖子与这个主题非常相关，因为攻击 LLM 本质上是控制模型输出某种类型（不安全的）内容。

“还有一类工作是攻击 LLM 以提取预训练数据、私有知识（Carlini et al, 2020）或通过数据投毒攻击模型训练过程（Carlini et al. 2023）。我们不会在本文中涵盖这些主题。”

还有一类工作是攻击 LLM 以提取预训练数据、私有知识（Carlini 等，2020）或通过数据投毒攻击模型训练过程（Carlini 等，2023）。我们不会在本文中涵盖这些主题。## 基础（Basics）

威胁模型（Threat Model）

"Adversarial attacks are inputs that trigger the model to output something undesired. Much early literature focused on classification tasks, while recent effort starts to investigate more into outputs of generative models. In the context of large language models In this post we assume the attacks only happen at inference time, meaning that model weights are fixed."

对抗性攻击是触发模型输出不需要内容的输入。早期文献主要集中在分类任务上，而最近的工作开始更多地调查生成模型的输出。在大型语言模型的上下文中，在本文中我们假设攻击只发生在推理时间，意味着模型权重是固定的。

分类（Classification）

"Adversarial attacks on classifiers have attracted more attention in the research community in the past, many in the image domain. LLMs can be used for classification too. Given an input $\mathbf{x}$ and a classifier $f(.)$, we would like to find an adversarial version of the input, denoted as $\mathbf{x}\text{adv}$, with imperceptible difference from $\mathbf{x}$, such that $f(\mathbf{x}) \neq f(\mathbf{x}\text{adv})$."

对分类器的对抗性攻击在过去的研究界引起了更多关注，许多在图像领域。LLM 也可以用于分类。给定输入 x 和分类器 f(.)，我们希望找到输入的对抗性版本，记为 x_adv，与 x 的差异不可察觉，使得 f(x) ≠ f(x_adv)。

文本生成（Text Generation）

"Given an input $\mathbf{x}$ and a generative model $p(.)$, we have the model output a sample $\mathbf{y} \sim p(.\vert\mathbf{x})$ . An adversarial attack would identify such $p(\mathbf{x})$ that $\mathbf{y}$ would violate the built-in safe behavior of the model $p$; E.g. output unsafe content."

给定输入 x 和生成模型 p(.)，我们让模型输出样本 y ~ p(.|x)。对抗性攻击将识别这样的 p(x)，使得 y 将违反模型 p 的内置安全行为；例如，输出不安全的内容。

白盒 vs 黑盒（White-box vs Black-box）

"White-box attacks assume the attacker has full access to the model, including architecture, weights, gradients, and training data. This enables precise gradient-based attacks."

白盒攻击假设攻击者可以完全访问模型，包括架构、权重、梯度和训练数据。这使得精确的基于梯度的攻击成为可能。

"Black-box attacks only have API access, meaning they can only observe outputs given inputs. This is more realistic for commercial models but limits attack precision."

黑盒攻击只有 API 访问权限，意味着它们只能观察给定输入的输出。这对商业模型更现实，但限制了攻击精度。## 对抗性攻击的类型（Types of Adversarial Attacks）

Token 操作（Token Manipulation）

"Token-level attacks manipulate the input tokens directly. Common strategies include: 1) Synonym replacement: Replace words with synonyms to bypass safety filters; 2) Paraphrase: Rewrite the prompt in a different style; 3) Typo injection: Add typos or unicode characters; 4) Token splitting: Split harmful tokens across boundaries."

Token 级攻击直接操纵输入 token。常见策略包括：1) 同义词替换：用同义词替换词以绕过安全过滤器；2) 释义：用不同风格重写提示；3) 错别字注入：添加错别字或 unicode 字符；4) Token 拆分：将有害 token 拆分到边界。

基于梯度的攻击（Gradient based Attacks）

"These attacks use the gradient of the model loss with respect to input tokens to find adversarial examples. They require white-box access but are very effective."

这些攻击使用模型损失相对于输入 token 的梯度来找到对抗性示例。它们需要白盒访问但非常有效。

越狱提示（Jailbreak Prompting）

"Jailbreak prompts are user inputs that bypass the safety guardrails of LLMs, causing them to generate harmful or unintended content. Common types include: 1) Role-playing prompts: 'Pretend you are an evil AI'; 2) Hypothetical scenarios: 'In a fictional world, how would you...'; 3) Token splitting: 'What is the opposite of [refusal behavior]?'; 4) Obfuscation: Using base64 or other encodings to hide harmful instructions."

越狱提示是绕过 LLM 安全护栏的用户输入，导致它们生成有害或意外的内容。常见类型包括：1) 角色扮演提示："假装你是一个邪恶的 AI"；2) 假设场景："在一个虚构的世界里，你会如何..."；3) Token 拆分："[拒绝行为]的反面是什么？"；4) 混淆：使用 base64 或其他编码来隐藏有害指令。

人在回路红队（Humans in the Loop Red-teaming）

"Human red-teaming involves having humans actively try to break the model's safety. This is the most effective method but also the most expensive."

人类红队涉及让人类积极尝试破坏模型的安全性。这是最有效的方法但也是最昂贵的。

模型红队（Model Red-teaming）

"Model red-teaming uses another AI model to automatically generate adversarial inputs. This is more scalable than human red-teaming but may miss subtle attacks that humans would catch."

模型红队使用另一个 AI 模型自动生成对抗性输入。这比人类红队更具可扩展性，但可能会错过人类会发现的微妙攻击。

窥视缓解（Peek into Mitigation）

鞍点问题（Saddle Point Problem）

"The challenge of LLM safety is fundamentally a saddle point problem: we need the model to be safe (avoid harmful outputs) AND helpful (follow user instructions). These two goals can conflict: a request to help with illegal activity is both helpful and harmful. The model needs to find a balance."

LLM 安全性的挑战本质上是一个鞍点问题：我们需要模型是安全的（避免有害输出）又有帮助的（遵循用户指令）。这两个目标可能会冲突：帮助非法活动的请求既是有帮助的又是有害的。模型需要找到一个平衡。

LLM 鲁棒性方面的一些工作（Some work on LLM Robustness）

"Researchers are working on multiple approaches to improve LLM safety: 1) Adversarial training: Train the model on adversarial examples; 2) Defensive prompting: Use safety prompts; 3) Output filtering: Filter outputs for harmful content; 4) Constitutional AI: Use a set of principles to guide the model; 5) RLHF: Reinforcement Learning from Human Feedback; 6) Red-teaming: Proactive testing for vulnerabilities."

研究人员正在研究多种方法来改进 LLM 安全性：1) 对抗性训练：在对抗性示例上训练模型；2) 防御性提示：使用安全提示；3) 输出过滤：过滤有害内容的输出；4) Constitutional AI：使用一组原则来指导模型；5) RLHF：从人类反馈进行强化学习；6) 红队：主动测试漏洞。## 引用（Citation）
