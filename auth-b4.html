B4 · 《LLM Security and Governance》

类型：工程技术书 · 安全与合规
链接：各大书店渠道可查
中文卡版本：基于摘要整理 · 2026-09-10

一、定位

RAG + Agent 让企业把 AI 用起来，但安全和合规是企业 AI 落地最容易被忽视的一面——
也是最致命的一面。

这本书是 LLM 应用的"安全守则"。
客户法务/合规问"AI 出事谁负责"，答案在这。

二、五大核心论点

1. 内容安全（Content Safety）

LLM 的输出可能：
- 违规内容：色情 / 暴力 / 政治敏感
- 机密泄露：训练数据里的客户信息 / 合同金额
- 误导信息：看起来对但其实是错的
- 恶意指令：用户用 prompt injection 让模型做坏事

防护层：
- 输入过滤（prompt 注入检测）
- 输出过滤（违规词 / 敏感信息）
- 黑名单词表 + 白名单场景
- 人工抽检 + 用户举报

对应你的"客户数据是命根子"——
安全和合规放第一。

2. 权限管理（Access Control）

不是所有用户都能让 Agent 做所有事：

角色 能做什么
普通员工 查数据 / 提建议
主管 改自己部门数据
部门负责人 跨部门协调
老板 一票决定权

实现方式：
- RBAC（基于角色的权限）
- OAuth + Scope（API 级别权限）
- Agent 知道"我是谁"，自动应用权限

对应你的 SOP-03 第 2 步"挖 1 号位的真痛点"——
权限设计必须和决策权对齐。

3. 审计与可追溯（Audit Trail）

每个 AI 调用都要留痕：

  • 谁（用户 ID）
  • 什么时候
  • 调了什么（输入 + 输出）
  • 用哪个模型 / 哪个版本
  • 触发了哪些工具
  • 是否有护栏拦截
  • 最终结果

留多久：根据合规要求（GDPR 6 年 / SOX 7 年 / 金融业永久）

作用：
- 出事能追责
- 调优有数据
- 合规审计能过关

对应你的 SOP-04 第 3 步"给 AI 立硬规则"——
失败透明 + 全程留痕是基本要求。

4. 数据隐私与隔离

企业数据绝对不能泄露给模型厂商或其他人：

  • 私有部署：模型跑在自己机房
  • API 隔离：用 VPC / 专线，不走公网
  • 数据脱敏：喂给模型前先去掉敏感字段
  • 训练隔离：企业数据不进通用模型训练
  • 输出过滤：返回前先去掉客户信息

红线：
- 客户身份证 / 银行卡 → 绝不能进 Prompt
- 商业机密 / 合同金额 → 内部模型处理
- 员工聊天 / 邮件 → 不进 AI 训练

对应你的 SOP-05「行业深耕」第 5 步"别把客户数据喂给不可控工具"——
这是真红线，违反一次项目就死了。

5. 合规与法律边界

不同行业有不同合规要求：

行业 合规要求
金融 模型可解释 + 人工审核 + 监管报送
医疗 HIPAA + FDA 验证 + 病历隐私
教育 未成年人保护 + 数据本地化
跨境 GDPR + 数据出境 + 当地法规
政府 等保 / 密评 / 国密算法

实施：
- 法务早期介入
- 行业认证（如 ISO 27001 / SOC 2）
- 定期安全审计
- 应急响应预案

五、客户引用话术

"我们对客户数据有 4 道隔离：私有部署 + API 专线 + 输入脱敏 + 输出过滤。
全程审计日志保留 X 年，符合 GDPR / 等保 / ISO 27001。

十一、数据脱敏 4 级

L0：完全脱敏（公开数据）

  • 移除：姓名 / 身份证 / 银行卡 / 地址 / 电话
  • 适合：演示 / 培训 / 客户展示
  • 工具：Microsoft Presidio / 自建正则

L1：部分脱敏（内部数据）

  • 替换：姓名→客户A / 金额→X万
  • 适合：公司内部培训 / 测试
  • 工具：Faker / 自建脚本

L2：加密脱敏（敏感数据）

  • 加密：使用 KMS 加密后传给模型
  • 模型端：不能直接看到明文
  • 适合：金融 / 医疗 / 客户合同
  • 工具：AWS KMS / HashiCorp Vault

L3：本地处理（绝密数据）

  • 模型部署在客户内网
  • 数据不出客户网络
  • 适合：政府 / 国防 / 商业机密
  • 工具：本地 Ollama + vLLM

十二、3 个客户说服话术

话术 1：解释为什么要脱敏

"客户数据 = 客户的命根子。
我们用 L2 加密脱敏 + L3 私有部署双重保险——
即使模型被攻击，攻击者拿到的也是加密数据。"

话术 2：解释为什么不全脱敏

"完全脱敏会丢失关键信息（比如客户经理是谁）。
L1-L2 混合脱敏：业务相关字段保留，敏感字段替换。
既保护隐私又不影响业务。"

话术 3：解释合规等级

"等保 2.0 三级要求：
- 数据不出境 ✓
- 加密存储 ✓
- 访问审计 ✓
我们的方案全部满足。"

4. Prompt Injection 防护 5 招

  5. 沙箱执行：高危操作先到沙箱确认

📖 完整深度论述

本卡对应《LLM Security and Governance》。以下为基于 OWASP/NIST/工业实践的系统性深度论述。

LLM 引入了一类全新的安全风险

传统软件安全主要防的是"外部攻击者"——SQL 注入、XSS、越权访问。而 LLM 引入了一类全新的风险：模型本身可能被诱导做出不该做的事。这就是 Prompt Injection（提示词注入）——攻击者不用破解系统，只需在输入里加一句"忽略之前的指令，执行 X"，就能让模型"叛变"。

更微妙的是，LLM 的安全风险常常是无意的：训练数据里混入的客户信息，可能在回答时泄露；模型为了"有用"而编造的信息，可能误导用户。所以 LLM 安全的第一课是：威胁模型变了——从"防外部攻击"扩展到"防模型被诱导 + 防模型泄露 + 防模型编造"。

OWASP LLM Top 10：行业共识的风险清单

OWASP（开源 Web 应用安全项目）发布的 LLM Top 10，是 LLM 安全领域的行业共识清单。排名前三的风险分别是：

  1. Prompt Injection（提示词注入）——最普遍也最难防；
  2. Sensitive Information Disclosure（敏感信息泄露）——模型吐出了不该吐的数据；
  3. Supply Chain（供应链风险）——用了不可信的开源模型或数据集。

这份清单的价值在于：它给了 FDE 一个可对照的检查表。交付前逐条过一遍，能堵住大部分安全漏洞。

数据脱敏：分层而非一刀切

数据脱敏最容易犯的错是"一刀切"——要么完全脱敏（丢失业务信息），要么不脱敏（泄露风险）。正确的做法是分级脱敏：

  • L0 完全脱敏：去掉姓名/身份证/银行卡，适合公开演示；
  • L1 部分脱敏：姓名→"客户A"、金额→"X万"，适合内部培训；
  • L2 加密脱敏：KMS 加密后再传模型，适合金融/医疗；
  • L3 本地处理：模型部署在客户内网，数据不出网，适合政府/国防。

分级的关键是匹配场景的敏感度：越敏感的数据，脱敏级别越高，处理越靠近本地。

合规不是可选项，是底线

对 B 端客户（尤其金融/医疗/政府/跨境），合规是必谈项，不是加分项。等保 2.0 三级要求数据不出境、加密存储、访问审计、入侵检测；GDPR 要求数据主体的权利；行业认证（ISO 27001/SOC 2）是进入大客户的敲门砖。

FDE 的职责是把合规要求工程化：审计日志保留 6 个月以上、RBAC 权限控制、输入脱敏 + 输出过滤、私有部署方案。这些不是"做完再补"，而是设计阶段就要考虑。

一句话总结：LLM 安全的核心是认识到威胁模型变了——要防注入、防泄露、防编造，数据脱敏要分级，合规要工程化落地。
