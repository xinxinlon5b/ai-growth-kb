B3 · Retrieval-Augmented Generation (RAG) —— 完整中文全文翻译

原文来源：综合自 Anthropic Claude RAG 文档、Pinecone Learning Center、LangChain RAG Tutorial、RAGAS GitHub Cookbook、AWS RAG 实践等多家官方/权威文档。
翻译说明：以下是基于多家权威文档完整中文翻译，保留 RAG 的定义、原理、5 步流程、7 种 Chunking 策略、4 大关键指标、4 种高级模式、6 大反模式、完整技术组件。

1. RAG 是什么？

"Retrieval-Augmented Generation (RAG) is a technique that enhances LLM outputs by retrieving relevant information from a knowledge base before generating a response. RAG addresses the limitations of LLMs, including outdated knowledge, hallucinations, and lack of domain-specific information."

检索增强生成（RAG）是一种通过在生成响应之前从知识库中检索相关信息来增强 LLM 输出的技术。RAG 解决了 LLM 的局限性，包括过时的知识、幻觉和缺乏特定领域的信息。

2. RAG 解决的 3 大根本问题

2.1 知识截止（Knowledge Cutoff）

"LLMs are trained on data up to a specific date and have no knowledge of events that occurred after that date. RAG addresses this by retrieving up-to-date information from external sources."

LLM 是在特定日期之前的数据上训练的，对该日期之后发生的事件一无所知。RAG 通过从外部源检索最新信息来解决这个问题。

2.2 幻觉（Hallucination）

"LLMs can confidently state incorrect information. RAG reduces hallucinations by grounding the model's responses in retrieved documents, making it less likely to generate false information."

LLM 可以自信地说出不正确的信息。RAG 通过将模型响应基于检索到的文档来减少幻觉，使其不太可能生成虚假信息。

2.3 无领域知识（No Domain Knowledge）

"LLMs don't have access to your private documents or proprietary information. RAG allows you to provide domain-specific knowledge without retraining the model."

LLM 无法访问您的私有文档或专有信息。RAG 允许您提供特定领域的知识而无需重新训练模型。

3. RAG 的 5 步标准流程

3.1 步骤 1：查询向量化（Query Embedding）

"The user's question is converted into a vector representation using an embedding model. The same embedding model that was used to index the documents should be used for queries to ensure consistency."

用户的问题使用嵌入模型转换为向量表示。应该使用与索引文档相同的嵌入模型来处理查询，以确保一致性。

3.2 步骤 2：检索（Retrieval）

"The query vector is used to search the vector database for the most similar documents. The number of documents to retrieve (top-k) is a key parameter that affects the quality and cost of the response."

查询向量用于在向量数据库中搜索最相似的文档。要检索的文档数量（top-k）是影响响应质量和成本的关键参数。

3.3 步骤 3：重排（Reranking）

"The retrieved documents are reranked using a more sophisticated model, such as a cross-encoder, to improve the relevance of the top results. This is especially important when the initial retrieval returns many documents of varying relevance."

使用更复杂的模型（如 cross-encoder）重新排序检索到的文档，以提高顶部结果的相关性。当初始检索返回许多相关性不同的文档时，这尤其重要。

3.4 步骤 4：构建 Prompt

"The reranked documents are used to construct a prompt for the LLM, along with the original query. The prompt typically includes instructions for the LLM to use the provided context to answer the question."

重新排序的文档与原始查询一起用于为 LLM 构建 prompt。prompt 通常包括指导 LLM 使用提供的上下文来回答问题的指令。

3.5 步骤 5：生成（Generation）

"The LLM generates a response based on the query and the retrieved context. The response should be grounded in the provided documents and should acknowledge when information is not available."

LLM 根据查询和检索到的上下文生成响应。响应应基于提供的文档，并在信息不可用时予以说明。

4. 7 种 Chunking 策略

4.1 固定大小（Fixed Size）

"Split text into chunks of a fixed number of characters or tokens. Simple but may split semantic units."

将文本拆分为固定数量的字符或 token 的块。简单但可能拆分语义单元。

4.2 按段落（By Paragraph）

"Split text at natural paragraph boundaries. Preserves semantic units better than fixed size."

在自然段落边界处拆分文本。比固定大小更好地保留语义单元。

4.3 按 Token（By Token）

"Split text based on token count, which is more aligned with how LLMs process text. Requires a tokenizer."

基于 token 数量拆分文本，更符合 LLM 处理文本的方式。需要一个 tokenizer。

4.4 按语义（By Semantic）

"Split text based on semantic similarity between sentences. More complex but produces semantically coherent chunks."

基于句子之间的语义相似性拆分文本。更复杂但产生语义连贯的块。

4.5 递归切分（Recursive）

"Split text using a hierarchy of separators, trying the largest separator first and falling back to smaller ones. Combines flexibility with semantic awareness."

使用层次分隔符拆分文本，首先尝试最大的分隔符，然后回退到较小的分隔符。结合灵活性与语义感知。

4.6 滑动窗口（Sliding Window）

"Create overlapping chunks to preserve context across boundaries. Useful when chunks are split mid-thought."

创建重叠的块以保留跨边界的上下文。当块在中间拆分时很有用。

4.7 小到大（Small-to-Big）

"Index small chunks for retrieval, but return larger chunks to the LLM for context. Combines precision of small chunks with context of large chunks."

索引小块用于检索，但返回大块给 LLM 作为上下文。结合小块精度与大块上下文。

5. 4 大关键指标

5.1 Recall@K（前 K 个结果中含正确答案的比例）

"The proportion of queries for which the correct answer is in the top K retrieved results. Target: > 0.80."

正确答案在前 K 个检索结果中的查询比例。目标：> 0.80。

5.2 MRR（平均倒数排名）

"The average of the reciprocal ranks of the first correct answer. Target: > 0.70."

第一个正确答案的倒数排名的平均值。目标：> 0.70。

5.3 Context Precision（上下文精确度）

"The proportion of relevant items in the retrieved context. Target: > 0.80."

检索上下文中相关项目的比例。目标：> 0.80。

5.4 Faithfulness（忠实度）

"The extent to which the generated answer is faithful to the retrieved context. Target: > 0.90."

生成的答案对检索上下文的忠实程度。目标：> 0.90。

6. 4 种高级 RAG 模式

6.1 Multi-Query Retrieval

"Use the LLM to rewrite the user's question into 3-5 different perspectives, then retrieve for each and merge the results. Improves recall by capturing different aspects of the query."

使用 LLM 将用户的问题改写为 3-5 个不同的视角，然后为每个视角检索并合并结果。通过捕获查询的不同方面来提高召回率。

6.2 HyDE（Hypothetical Document Embeddings）

"Generate a hypothetical answer to the query, then use that as the embedding for retrieval. The hypothesis answer is semantically closer to the actual answer than the question itself."

为查询生成一个假设性答案，然后将其用作检索的嵌入。假设性答案在语义上比问题本身更接近实际答案。

6.3 Self-RAG

"The model decides when to retrieve, judges the quality of retrieved documents, and can iterate until satisfied. More autonomous but more complex."

模型决定何时检索，判断检索文档的质量，并可以迭代直到满意。更自主但更复杂。

6.4 GraphRAG

"Build a knowledge graph from documents, then use it for multi-hop question answering. Better for questions that require connecting information across multiple sources."

从文档构建知识图谱，然后用于多跳问题回答。更好地需要跨多个源连接信息的问题。

7. 6 大反模式

7.1 把所有内容塞进 prompt

"Don't put entire documents in the prompt. Use retrieval to get only the relevant parts."

不要将整个文档放入 prompt。使用检索仅获取相关部分。

7.2 不评估就上线

"Always evaluate RAG before deploying. Use the metrics above to measure performance."

在部署之前始终评估 RAG。使用上述指标衡量性能。

7.3 忽略 chunking

"Chunking is critical. Bad chunking leads to bad retrieval. Experiment with different strategies."

分块至关重要。糟糕的分块导致糟糕的检索。尝试不同的策略。

7.4 不重排序

"Initial retrieval is often not optimal. Use a reranking model to improve relevance."

初始检索通常不是最优的。使用重排序模型提高相关性。

7.5 不处理空检索

"If retrieval returns no results, the LLM has nothing to work with. Have a fallback strategy."

如果检索不返回结果，LLM 就没有可处理的内容。有一个回退策略。

7.6 不监控

"Monitor RAG performance in production. Performance can degrade over time as data changes."

在生产中监控 RAG 性能。随着数据变化，性能可能会下降。

8. RAG 完整技术组件

  1. 文档加载器（Document Loaders）：从各种源加载文档
  2. 文本分割器（Text Splitters）：将文档分割成块
  3. 嵌入模型（Embedding Models）：将文本转换为向量
  4. 向量数据库（Vector Stores）：存储和检索向量
  5. 检索器（Retrievers）：从向量数据库检索相关文档
  6. 重排器（Rerankers）：重新排序检索结果
  7. LLM：生成最终响应
  8. 评估框架：测量 RAG 性能
