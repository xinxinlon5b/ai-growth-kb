E5 · 企业架构与治理标准（TOGAF + PMBOK + ISO 42001 + 三家云 WAF）

类型：企业架构 / 项目管理 / AI 治理国际标准
来源：The Open Group / PMI / ISO / AWS / Azure / GCP 官方
中文卡版本：基于 DeerFlow 调研整理 · 2026-09-10

一、定位

这张卡是「客户 CIO/CTO 谈 FDE 时最有分量的国际标准弹药」。
FDE 做的不是小项目，是企业级 AI 系统——必须按国际标准来。

二、TOGAF 10 ADM（The Open Group Architecture Framework）

企业架构领域唯一被广泛采用的国际标准。

TOGAF 10 Architecture Development Method（ADM）核心循环：
- Phase A：架构愿景
- Phase B：业务架构
- Phase C：信息系统架构（数据 + 应用）
- Phase D：技术架构
- Phase E：机会与解决方案
- Phase F：迁移规划
- Phase G：实施治理
- Phase H：架构变更管理
- 强项：企业架构层的 H 变更管理（唯一强覆盖）

适用场景：客户组织 > 500 人 / 多部门 / 长期演进。

三、PMBOK 8（PMI 项目管理体系）

项目管理横切层——不只覆盖软件开发，覆盖任何项目类型。

PMBOK 8 = 7 个绩效域：
1. 团队
2. 规划
3. 不确定性
4. 交付
5. 度量
6. 业务
7. 干系人

适用场景：交付节奏管理 / 客户沟通 / 干系人管理。

四、ISO/IEC 42001:2023（AI 管理体系）

全球第一个 AI 管理国际标准。

核心结构：
- 治理（Govern）
- 数据（Data）
- AI 影响评估（AI Impact Assessment）
- 模型退役（Model Retirement）
- 强项：Discover（AI 影响评估） + Data（数据治理） + Retire（模型退役）——这些是工程框架的天然空白

https://www.iso.org/standard/42001
适用场景：合规要求高的行业（金融/医疗/政府/跨境）。

五、三家云 Well-Architected Framework

厂商 框架 特色
AWS Well-Architected Framework + ML Lens 5 支柱 + ML 专门透镜
Azure Well-Architected Framework + AI Workload 强调 AI 系统的非确定性
GCP Architecture Framework + AI&ML Perspective 强在 Design→Operate→Iterate

三家的 5 支柱同构：
- Security（安全）
- Reliability（可靠性）
- Performance Efficiency（性能）
- Cost Optimization（成本）
- Operational Excellence（运营卓越）
- （GCP 加 Sustainability 可持续性）

适用场景：见云客户时引用对应的"那家"的 WAF。

六、12 阶段对照表

12 阶段 × 6 权威框架覆盖（DeerFlow 调研 R4 §7）：

阶段 覆盖它的框架
B1 项目立项 PMBOK
B2 业务建模 TOGAF B/C
B3 需求 SWEBOK 需求 KA
B4 架构 TOGAF D + AWS WAF
B5 实现 SWEBOK 构造 + Scrum
B6 测试 SWEBOK 测试 + DORA

每个阶段都能查到哪个标准给了要求——见客户时按客户痛点找对应标准。

十一、5 个常见选型决策树

决策 1：项目管理用 PMBOK 还是 Scrum？

团队规模 < 5 人 + 业务明确 → Scrum
团队规模 5-20 人 + 多项目 → PMBOK + 敏捷混合
团队规模 > 20 人 + 长周期 → PMBOK

决策 2：企业架构用 TOGAF 还是 Zachman？

国际客户 / 大型组织 → TOGAF
北美传统企业 → Zachman
中小型 / 互联网 → 不需要正式框架

决策 3：AI 治理用 ISO 42001 还是 NIST RMF？

欧盟市场 → ISO 42001（合规）
美国市场 → NIST RMF（事实标准）
全球 → 两个都做

决策 4：云架构参考 AWS / Azure / GCP 哪一家？

AWS 重度 → AWS WAF + ML Lens
Azure 重度 → Azure WAF + AI Workload
GCP 重度 → GCP Architecture Framework
多云 → 三家都参考

决策 5：要不要上 CMMI 5 级？

咨询公司 / 上市准备 → 是
普通产品公司 → 不必
服务公司 → 选 3 级即可

十二、3 个反模式

反模式 1：全选

症状：PMBOK + TOGAF + ISO 42001 + AWS WAF 全部上。
风险：合规成本超过价值。
正解：根据行业 / 客户 / 规模选 1-2 个。

反模式 2：跟客户标准走

症状：客户用什么你就用什么。
风险：被客户的标准绑架。
正解：用业界主流 + 解释选择理由。

反模式 3：忽略国际标准

症状：只用国内标准。
风险：出海 / 跨国客户无法对接。
正解：国际标准做基线 + 国内标准做补充。
