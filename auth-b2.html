一、定位

如果说 B1（Pete Hunt）讲的是 LLM 应用怎么生产化，
那 B2 讲的是 Agent 系统怎么架构设计——是 A2（生产级 Agent 白皮书）的工程化展开。

这本是 Agent 架构圣经。
客户问"你们的 Agent 跟竞品有什么不同"，答案在架构层面。

二、五大核心论点

1. Agent 编排范式（Orchestration Patterns）

不是所有 Agent 都一样，按编排方式分：

范式 特征 适合场景
单 Agent + 工具 一个大脑调 N 个工具 客服 / 简单问答
多 Agent 流水线 Agent1 → Agent2 → Agent3 文档处理 / 多步骤流程
多 Agent 协作 多个 Agent 互相调用 复杂决策 / 模拟场景
Agent + 人工 Agent 提议 + 人工确认 高风险业务

对应你 SOP-03 第 3 步"立刚性规则再谈 AI"——
风险越高的业务，越要选人机协作范式。

2. 状态管理（State Management）

Agent 是有状态的，状态管理是 Agent 系统最难的工程问题：

  • 会话状态：当前对话上下文
  • 任务状态：执行到哪一步了
  • 业务状态：操作数据库产生的真实数据
  • 记忆状态：长期记忆 / 用户偏好

反模式：把状态全塞进 Prompt → Token 爆炸 + 性能崩
正解：分层存储 + 摘要 + 外部记忆库

对应你 SOP-04「Agent 工具链」第 3 步"给 AI 立硬规则"——
状态要显式管理，不能靠 Prompt 隐性传递。

3. Tool / Skill 的封装、版本、复用

Tool 和 Skill 不是"调一个 API 那么简单"，要：

  • 封装：统一接口（输入输出 schema）
  • 版本：每个 Tool 有版本号，老调用不破坏
  • 复用：跨 Agent 共享 Tool 库
  • 测试：每个 Tool 独立可测
  • 监控：Tool 调用成功率、延迟、成本

对应你 SOP-04 第 5 步"沉淀成 Skill"——
Skill 不沉淀，Agent 就是一次性玩具。

4. Harness / Guardrail / 业务回滚（与 A2 呼应）

A2 讲了概念，B2 给了实现细节：

概念 实现方式
Harness 一个 Python/TS 类，包裹 Agent 调用
Guardrail 输入校验器 + 输出过滤器 + 动作拦截器
业务回滚 Saga 模式 / 补偿事务 / 软删除 + 反向操作

业务回滚 ≠ 模型回滚：
- 模型回滚：换回老模型版本
- 业务回滚：撤销 Agent 已经造成的业务影响（发出去的邮件撤回、创建的订单取消、转账退款）

对应你 SOP-03 第 4 步"留人工兜底验收"——
业务回滚是护栏的最后一道防线。

5. 高危动作拦截 + 人工接管

按动作风险分级处理：

动作 风险 处理
查订单 L0 Agent 自动
改备注 L1 Agent 自动 + 日志
发邮件 L2 Agent 提交 + 异步通知
退款 < 1000 元 L3 Agent 提交 + 人工确认
退款 > 1000 元 L4 必须人工执行

对应你 SOP-07「报价签约」交付标准——
风险分级要写进合同，不能口头约定。

十一、State Management 4 层架构

第 1 层：会话状态（Session State）

  • 存什么：当前对话上下文（最近 N 轮）
  • 存哪：Redis / 内存
  • TTL：对话结束 N 分钟后清

第 2 层：任务状态（Task State）

  • 存什么：当前任务进度（已做 / 待做 / 失败）
  • 存哪：PostgreSQL / SQLite
  • TTL：任务结束 N 天后归档

第 3 层：业务状态（Business State）

  • 存什么：Agent 操作产生的真实业务数据
  • 存哪：业务系统（订单表 / 用户表）
  • TTL：跟随业务规则

第 4 层：记忆状态（Memory State）

  • 存什么：用户长期偏好 / 历史交互
  • 存哪：向量数据库 / 长期存储
  • TTL：永久（用户可删）

十二、3 个反模式

反模式 1：把状态全塞进 Prompt

症状：把所有历史塞进 system prompt。
风险：Token 爆炸 + 性能崩 + 上下文窗口超限。
正解：分层存储 + 摘要压缩 + 按需加载。

反模式 2：状态不持久化

症状：Agent 重启后丢失所有上下文。
风险：用户体验断层 + 数据丢失。
正解：关键状态写数据库（不是只放内存）。

反模式 3：忽略状态同步

症状：Agent 改了业务数据，但业务系统没收到通知。
风险：数据不一致 + 业务流程断。
正解：事件驱动 + 消息队列 + 同步机制。
