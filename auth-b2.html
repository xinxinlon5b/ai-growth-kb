B2 · Designing Agentic Systems —— 完整中文全文翻译

1. 什么是 Agent 系统？

"An agentic system is a software system that uses Large Language Models to reason about goals, plan actions, and execute those actions in an environment to achieve objectives. Unlike traditional software, agentic systems operate in environments with uncertainty, where the right action is not always known in advance."

Agentic 系统是一种使用大型语言模型来推理目标、规划行动并在环境中执行这些行动以实现目标的软件系统。与传统软件不同，agentic 系统在不确定性的环境中运行，其中正确的行动并不总是事先知道。

2. 为什么需要专门设计 Agent 系统？

"LLMs are powerful but unpredictable. They can generate creative, contextually appropriate responses, but they can also hallucinate, fail at complex reasoning, and struggle with long-horizon tasks. Designing agentic systems is the discipline of structuring LLM interactions to maximize their capabilities while mitigating their limitations."

LLM 强大但不可预测。它们可以生成创造性的、上下文相关的响应，但也可能产生幻觉、在复杂推理中失败，并难以处理长期任务。设计 agentic 系统是构建 LLM 交互以最大化其能力同时缓解其局限性的学科。

3. 4 层架构（Adele Lin 框架）

3.1 Reasoning 层（推理层）

"The reasoning layer is responsible for understanding the user's request, planning a course of action, and making decisions about how to proceed. This is where the LLM's 'thinking' happens."

推理层负责理解用户请求、规划行动方案并就如何进行做出决定。这是 LLM 的"思考"发生的地方。

3.1.1 Chain-of-Thought（思维链）

"Chain-of-Thought (CoT) prompting encourages the model to think step by step before arriving at a final answer. This improves performance on tasks that require multi-step reasoning."

Chain-of-Thought（CoT）提示鼓励模型在得出最终答案之前逐步思考。这改善了需要多步推理的任务上的性能。

3.1.2 ReAct（推理+行动）

"ReAct combines reasoning and acting in an iterative loop: Thought → Action → Observation → Thought → Action. This allows the model to interleave internal reasoning with external actions, such as tool use."

ReAct 在迭代循环中结合推理和行动：思考 → 行动 → 观察 → 思考 → 行动。这允许模型将内部推理与外部行动（如工具使用）交织。

3.1.3 Plan-and-Execute（先规划后执行）

"Plan-and-Execute separates planning from execution. The model first creates a complete plan, then executes it step by step. This is useful for complex tasks that benefit from global reasoning."

Plan-and-Execute 将规划与执行分离。模型首先创建一个完整计划，然后逐步执行。这对于受益于全局推理的复杂任务很有用。

3.2 Memory 层（记忆层）

"The memory layer manages the agent's state across interactions. Without memory, agents cannot maintain context, learn from experience, or handle multi-turn conversations."

记忆层跨交互管理代理的状态。没有记忆，代理无法维护上下文、从经验中学习或处理多轮对话。

3.2.1 短期记忆（Short-Term Memory）

"Short-term memory holds the current conversation context, including recent messages, tool results, and the agent's current plan. This is typically managed by the LLM's context window."

短期记忆保存当前对话上下文，包括最近的消息、工具结果和代理的当前计划。这通常由 LLM 的上下文窗口管理。

3.2.2 长期记忆（Long-Term Memory）

"Long-term memory persists across sessions and includes user preferences, past interactions, and learned facts. This is typically stored in a vector database or knowledge graph."

长期记忆跨会话持久化，包括用户偏好、过去的交互和学习到的事实。这通常存储在向量数据库或知识图谱中。

3.2.3 程序记忆（Procedural Memory）

"Procedural memory stores how to perform tasks—essentially the agent's skills. This is often implemented as a library of tools or a set of instructions."

程序记忆存储如何执行任务——本质上是代理的技能。这通常实现为工具库或一组指令。

3.2.4 实体记忆（Entity Memory）

"Entity memory tracks information about specific entities (people, places, things) that the agent encounters. This is useful for maintaining context across conversations."

实体记忆跟踪代理遇到的具体实体（人、地、物）的信息。这对于跨对话维护上下文很有用。

3.3 Tools 层（工具层）

"The tools layer enables agents to interact with external systems, retrieve information, and perform actions. Tools are the primary mechanism by which agents affect the world."

工具层使代理能够与外部系统交互、检索信息并执行操作。工具是代理影响世界的主要机制。

3.3.1 信息获取工具（Information Retrieval）

"Tools that retrieve information without modifying state, such as search engines, databases, and document retrieval systems."

检索信息而不修改状态的工具，如搜索引擎、数据库和文档检索系统。

3.3.2 状态修改工具（State Modification）

"Tools that modify state, such as creating database records, sending emails, or updating files. These require appropriate safeguards."

修改状态的工具，如创建数据库记录、发送电子邮件或更新文件。这些需要适当的保障措施。

3.3.3 计算执行工具（Computational）

"Tools that perform computations, such as running Python code, executing SQL queries, or performing mathematical operations."

执行计算的工具，如运行 Python 代码、执行 SQL 查询或执行数学运算。

3.4 Orchestration 层（编排层）

"The orchestration layer coordinates the interaction between reasoning, memory, and tools. It defines the overall flow of the agentic system."

编排层协调推理、记忆和工具之间的交互。它定义了 agentic 系统的整体流程。

3.4.1 Sequential（顺序）

"Sequential orchestration executes components in a fixed order. This is the simplest pattern and is appropriate for linear workflows."

顺序编排按固定顺序执行组件。这是最简单的模式，适用于线性工作流。

3.4.2 Parallel（并行）

"Parallel orchestration executes multiple components simultaneously. This is useful for tasks that can be parallelized for speed."

并行编排同时执行多个组件。这对于可以并行化以提速的任务很有用。

3.4.3 Hierarchical（层级）

"Hierarchical orchestration uses a coordinator agent that delegates to worker agents. This is useful for complex tasks with sub-tasks."

层级编排使用协调者代理委派给工作代理。这对于具有子任务的复杂任务很有用。

3.4.4 Loop（循环）

"Loop orchestration iterates a component until a condition is met. This is useful for tasks that require iteration, such as refinement or exploration."

循环编排迭代一个组件直到满足条件。这对于需要迭代的任务（如精炼或探索）很有用。

4. 3 大核心技术

4.1 Memory Management（记忆管理）

"Effective memory management is critical for agent performance. This includes deciding what to remember, when to forget, and how to retrieve relevant memories."

有效的记忆管理对代理性能至关重要。这包括决定记住什么、何时忘记以及如何检索相关记忆。

4.2 Tool Use（工具使用）

"Tool use is the primary mechanism by which agents affect the world. Effective tool use requires: clear tool definitions, appropriate error handling, and result interpretation."

工具使用是代理影响世界的主要机制。有效的工具使用需要：清晰的工具定义、适当的错误处理和结果解释。

4.3 Planning（规划）

"Planning is the process of breaking down a complex task into manageable steps. This can be done by the agent itself (dynamic planning) or pre-defined (static planning)."

规划是将复杂任务分解为可管理步骤的过程。这可以由代理本身（动态规划）或预定义（静态规划）完成。

5. 4 种编排模式

5.1 Prompt Chaining（提示链）

"Prompt chaining decomposes a task into a sequence of steps, where each LLM call processes the output of the previous one. Programmatic checks (gates) can be added between steps."

提示链将任务分解为一系列步骤，其中每个 LLM 调用处理前一个的输出。程序化检查（gates）可以添加在步骤之间。

5.2 Routing（路由）

"Routing classifies an input and directs it to a specialized follow-up task. This allows for separation of concerns and building more specialized prompts."

路由对输入进行分类并将其引导到专门的后续任务。这允许关注点分离和构建更专门的提示。

5.3 Parallelization（并行化）

"Parallelization runs multiple LLM calls simultaneously and aggregates their outputs. This is useful for tasks that can be parallelized for speed or for getting multiple perspectives."

并行化同时运行多个 LLM 调用并聚合它们的输出。这对于可以并行化以提速或获得多个视角的任务很有用。

5.4 Orchestrator-Workers（编排者-工人）

"In the orchestrator-workers pattern, a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results. This is useful for complex tasks where the subtasks can't be predicted in advance."

在编排者-工人模式中，中央 LLM 动态分解任务，将其委派给工人 LLM，并合成它们的结果。这对于无法提前预测子任务的复杂任务很有用。

6. 7 大反模式

6.1 裸调模型（Calling LLM Directly）

"Calling the LLM directly without any harness, tools, or memory. This results in unpredictable behavior and no audit trail."

直接调用 LLM 而没有任何 harness、工具或记忆。这导致不可预测的行为且没有审计跟踪。

6.2 把所有状态塞进 Prompt

"Stuffing all state into the prompt. This causes context window overflow, performance issues, and difficulty debugging."

将所有状态塞进 prompt。这导致上下文窗口溢出、性能问题和调试困难。

6.3 让所有动作都自动执行

"Having the agent automatically execute all actions, including high-risk ones. This can lead to irreversible mistakes."

让代理自动执行所有操作，包括高风险操作。这可能导致不可逆转的错误。

6.4 忽略错误

"Ignoring errors and letting the agent continue. This can compound errors and lead to cascading failures."

忽略错误并让代理继续。这可能使错误复合并导致级联失败。

6.5 没有评测

"Deploying without proper evaluation. This makes it impossible to know if the agent is improving or degrading over time."

没有适当评估就部署。这使得不可能知道代理是否随着时间改善或退化。

6.6 循环无界

"Allowing the agent to loop without bounds. This can lead to infinite loops and excessive resource consumption."

允许代理无界循环。这可能导致无限循环和过多的资源消耗。

6.7 工具过大

"Building tools that do too much. This makes them hard to use and test. Tools should be small and focused."

构建做太多事情的工具。这使得它们难以使用和测试。工具应该小而专注。
