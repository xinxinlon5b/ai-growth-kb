E6 · FDE 三原厂官方定义（Palantir + OpenAI + Anthropic）

类型：一手权威 · FDE 角色定义

一、定位

这张卡强化 A1（Anthropic FDE 博客）——把"FDE 是哪三家原厂定义的"一次性说清。
见客户 / 写方案 / 做分享时，这是最能立权威的一手源。

二、Palantir —— FDE 的发明者

Palantir 官方文档对 FDE 的定义（来自 palantir.com/docs/foundry/architecture-center/platforms）：

"Product development paradigm... human equivalent of backpropagation"
（产品开发范式……人类版的反向传播）

FDE = 把现场反馈传回产品——这是 FDE 这个角色最原初的含义。

https://www.palantir.com/docs/foundry/architecture-center/platforms

三、OpenAI —— 2025 成立 The OpenAI Deployment Company

OpenAI 官方业务页（openai.com/business/the-openai-deployment-company/）：

"FDE is how OpenAI brings AI into production for complex, real-world use cases"
（FDE 是 OpenAI 把 AI 带到真实生产用例的方式）

关键动作：2025 年 OpenAI 专门成立 The OpenAI Deployment Company——把 FDE 业务独立成公司，这是 FDE 在 AI 时代被最大化的标志。

https://openai.com/business/the-openai-deployment-company/

四、Anthropic —— Applied AI 团队的 FDE 岗位

Anthropic 官方招聘 JD（anthropic.com/careers/jobs/5302966008）：

"Embed directly with strategic customers to drive transformational AI adoption"
（直接嵌入战略客户，推动变革性 AI 采用）

JD 关键词（原厂共识）：
- MCP servers（Model Context Protocol 服务）
- sub-agents（子智能体）
- agent skills（智能体技能）
- agentic systems（智能体系统）

https://www.anthropic.com/careers/jobs/5302966008

五、3 家交付物形态对比

厂商 交付物形态 核心能力
Palantir 本体模型（Ontology） + 数据集成 业务实体建模 + 数据接入
OpenAI 部署公司 + Assistants API AI 能力产品化
Anthropic Claude API + MCP + Skills Agent 工程化基础设施

共同点：都是"驻场 + 端到端 + 对业务结果负责"——这正是 FDE 的核心定义。

六、FDE ≠ 售前/咨询/外包的 3 大区别

角色 写代码 交付终点 收费
售前 偶尔 demo 拿到单 项目比例
咨询 不写 报告 + 建议 人月计费
外包 写 客户验收单 人月计费
FDE 写生产代码 客户团队改变工作方式 结果/阶段收费

FDE = 写的是生产环境代码 + 终点是组织改变 + 按结果/阶段收费。

十一、3 家 FDE 详细对比

Palantir FDE

  • 历史：FDE 这个词的发源地（2008+）
  • 核心交付物：Ontology + Foundry 平台
  • 典型客户：政府 / 国防 / 大型金融
  • FDE 特点：技术深度高 / 项目周期长（6-18 月）
  • 薪酬：$200K-$500K USD/年
  • 适合你接的客户类型：大型政企 / 长周期项目

OpenAI FDE

  • 历史：2023 年起 / 2025 年成立 The OpenAI Deployment Company
  • 核心交付物：Assistants API + Custom GPT + Agent SDK
  • 典型客户：中型企业 / 互联网公司
  • FDE 特点：产品化思维 / 标准化交付 / 周期短（4-8 周）
  • 薪酬：$150K-$300K USD/年
  • 适合你接的客户类型：中型企业 / AI 转型项目

Anthropic FDE

  • 历史：2024 年起 / Applied AI 团队
  • 核心交付物：Claude API + MCP + Skills
  • 典型客户：科技公司 / 研究机构
  • FDE 特点：技术前沿 / 强调 Agent 工程化
  • 薪酬：$200K-$400K USD/年
  • 适合你接的客户类型：技术驱动型 / AI 创新项目

十二、3 个共性（所有 FDE 都必须做）

共性 1：驻场

不是远程写代码，是到客户现场（线上或线下）。

共性 2：对业务结果负责

不是"代码上线"，是"客户业务改变"。

共性 3：沉淀可复用资产

每一次交付都为下一次交付修路。

十三、3 个反模式

反模式 1：照搬某一家

症状：完全按 Palantir 模式做（重平台重定制）。
风险：不适合中小客户。
正解：按客户规模 / 行业选模式。

反模式 2：FDE = 高级外包

症状：FDE 按工时计费。
风险：客户把你当外包。
正解：按结果 / 阶段收费。

反模式 3：不沉淀

症状：每个客户从零开始。
风险：没有复利。
正解：沉淀 Skill / 模板 / 组件库。

十一、原文核心（Palantir Foundry 官方 + OpenAI Deployment Company 官方）

来源：https://www.palantir.com/docs/foundry/architecture-center/platforms

1. Palantir Foundry 的 Ontology 概念（原文）

Palantir 把企业的"对象 + 链接 + 动作"建为本体（Ontology）：

"The Ontology is the foundation of Foundry. It models your business as objects, links, functions, and actions.
Objects represent real-world entities. Links represent relationships between objects.
Functions represent computations on objects. Actions represent changes to objects."

翻译：Ontology 把业务建模为：
- Objects（对象）：现实世界实体（订单、客户、设备）
- Links（链接）：对象之间的关系
- Functions（函数）：基于对象的计算
- Actions（动作）：对对象的修改

2. FDE 在 Palantir 的角色（原文）

"Forward Deployed Engineers embed with strategic customers to deliver production-grade
data and analytics capabilities. They serve as the technical interface between
Palantir's platform and customer business needs."

关键：FDE 是平台（Palantir Foundry）和客户业务之间的技术接口。

3. Ontology 与 DDD 的关系

Palantir Ontology DDD 概念
Objects Entities / Aggregates
Links Relationships
Functions Domain Services
Actions Aggregates / Commands

"Palantir 的 Ontology 本质是 DDD 的工程化实现 —— 把领域建模变成可视化平台"

4. OpenAI Deployment Company（2025 年成立）

官方页面核心：

"FDE is how OpenAI brings AI into production for complex, real-world use cases.
The OpenAI Deployment Company exists to scale this practice globally."

关键动作：
- 2025 年 OpenAI 独立成立 The OpenAI Deployment Company
- 专门负责 FDE 业务
- 把 FDE 从"部门职能"升级为"独立公司"

为什么：
- 标志 FDE 模式在 AI 时代被最大认可
- 客户愿意为 FDE 服务付高价
- 行业其他公司（Anthropic / 各大咨询公司）跟随

原文：AIP, Foundry, and Apollo（Palantir 官方架构中心）
来源：https://www.palantir.com/docs/foundry/architecture-center/platforms

集成平台：AIP、Foundry、Apollo

标准的 Palantir 架构由三个集成平台组成：AIP、Foundry、Apollo。

  • Apollo 是持续交付平台，管理承载 Foundry 和 AIP 服务的底层基础设施。Apollo 能每天跨数百个服务和资产编排数千次零停机升级。
  • Foundry 是基础数据运营平台，提供数据管理、逻辑编写、Ontology 开发、分析、工作流开发的核心能力。
  • AIP 是生成式 AI 平台，通过 "k-LLM" 范式提供与大语言模型的安全连接、构建智能体和自动化的开发工具链、一系列 AI 赋能的终端用户应用、以及一个用于治理生产 AI 工作流的综合 Evals 框架。

AIP + Foundry + Apollo：企业操作系统

集成的 AIP + Foundry + Apollo 架构被设计为企业操作系统（Enterprise Operating System）。

合在一起，AIP + Foundry 可以从概念上映射为九个能力集：
1. Ontology 系统：Ontology Language + Ontology Engine + Ontology Toolchain；
2. 数据/逻辑/工作流服务：Data Services + Logic Services + Workflow Services，为 Ontology 系统提供动力；
3. 分析应用 + 自动化 + 产品交付工具链：Analytics & Applications + Automations + Product Delivery toolchain。

这九个能力集整体性地利用六个网格级组件：Storage、Compute、Networking、Security、Governance、Workspace——全部由 Apollo 驱动。

Ontology（本体）—— Palantir 的核心概念

"The Ontology is the foundation of Foundry. It models your business as objects, links, functions, and actions."

Ontology 是 Foundry 的基础。它把你的业务建模为：
- Objects（对象）：代表现实世界实体；
- Links（链接）：代表对象之间的关系；
- Functions（函数）：代表对对象的计算；
- Actions（动作）：代表对对象的修改。

统一安全架构

统一安全架构横跨三个平台（AIP、Foundry、Apollo），涵盖三个主要领域：基础设施安全、平台安全、企业安全。

基础设施层面：Palantir 服务网格中的每个组件都采用 zero trust（零信任） 运行——所有元素都基于身份、设备健康、验证进行访问门控，并预期会有敌意攻击、需要自主执行（如通过 Apollo 强制的加密、防火墙、运行时配置）。

平台层面：Foundry 和 AIP 都提供实现可信协作所需的完整控制，包括严格强制人类和智能体的访问范围、细粒度的基于角色/标记/目的的访问控制，连接自动化血缘和审计，以及一系列平台内应用。

企业安全层面：加密、审计日志、授权、认证配置能深度集成到组织现有的身份提供商、信息安全工具和架构模式中。

实际应用场景

这套架构为以下场景提供动力：
- 大型医院系统的 AI 赋能护理运营；
- 大型航空公司的集成网络规划；
- 美国最大公用事业公司的电力运营和野火响应；
- 美国及其盟国的全频谱军事行动；
- 数千个其它用例。
